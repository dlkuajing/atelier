# Phase 14：CODE V TOR 真公差良率设计（真机证据修订版）

## 1. 目标与不可越过的边界

TOR 是离线、可审计的候选设计证据。AI 不生成或改写公差、补偿器、阈值或处方坐标，
也不作“量产合格”判断。只有完整运行、严格结构解析、trial 全覆盖、口径经资深 ratify
后，后续唯一 evidence factory 才可构造 `available/codev-tor-mc`；本铲 parser 的封闭枚举
只有 `unavailable`，调用方不能经该接口伪造 available。[M4]

proxy 与 TOR 是不同测量对象。缺许可证、超时、导出不全、schema 不符、trial 缺失、数值
非法、配置未 ratify 或阈值未 ratify，一律 unavailable；不得拿 proxy 回填 TOR。

## 2. 一手证据与已确认语法

手册依据是本机 CODE V 11.5 `D:\CODEV115\doc\Tolerancing.pdf`。2026-07-11 真机探针、
listing 摘录、退出码和逐字节 fixture 见
`.planning/loop/p14-tor-probe-evidence.md`；原始导出固化于 `tests/data/codev_tor/`。[B1]

真机已确认：

- `DEF TOL` 必须带 `Sk` 或 `Si..j` 面范围；裸命令非法。builder 对所有 `DEF TOL` 做
  面范围契约校验。默认公差只可作 smoke，不是量产标准。[B1]
- `WBF B1 PER` 与 `WBF B2 MC` 先选择两个独立 buffer，一次 `GO` 即同时产出；随后分别
  `BUF EXP B1`、`BUF EXP B2`。NTR20 全链约 2.3 秒。[B1]
- 进程 rc=1 时文件仍有效；铲 2 runner 必须沿用显式文件完整性契约与
  `allow_nonzero_ok_result`，不能只看退出码。
- MTF fixture 明示 `Azimuth=90`；builder 默认值固定为 90°（tangential），且总是发
  `AZI 90`，不再依赖 CODE V 暗默认。其他方位须显式传参；本铲仍只支持全局 FRE/AZI，
  不冒充逐 field/zoom 通用配置。[M2]
- PER 的 50.0/84.1/97.7/99.9 概率位列出现超 `[0,1]` 数值，数值语义未钉死；parser
  只保留结构化值，禁止据此算 yield。MC 的 `Sample/Zoom/Field/Criterion/Value` 可作为
  后续良率原料，但 0/1 饱和语义仍待阳性对照。[M4]

## 3. Builder 安全契约与批处理链

当前接口明确是 **ZMX-only**：非 `.zmx` 输入 fail closed；原生 `.seq/.len` 须另建经真机
验证的入口。[m1] PER、MC、source 三个路径必须互异，避免覆盖与双文件假象。[M3]

```text
IN CV_MACRO:ZEMAXOS_TO_CV <zmx>
<非空、资深批准、DEF TOL 带面范围的 tolerance commands>
<非空、资深批准的 compensator commands>
TOR
FRE <frequency>       # MTF only
AZI <degrees>         # MTF only；默认显式 90
NTR <trials>
CHT N
WBF B1 PER
WBF B2 MC
GO
BUF EXP B1 <per-path>
BUF EXP B2 <mc-path>
```

`metric` 在运行时只接受 `mtf|rms`；大小写或拼写错误立即拒绝，绝不静默退化成 RMS。
MTF frequency/azimuth 必须有限且在合法范围；RMS 禁止携带 MTF 参数。[M1]

commands 必须是非空单命令行，拒绝 CR/LF 与分号复合命令。provenance 与量产装调假设是
结构化注释字段：拒绝 CR/LF，且拒绝以 CODE V 命令词开头，元数据永远没有执行能力。
[B2][m2] `seed` 已从模型删除：目前没有 CODE V 11.5 seed 命令的一手证据，不能记录一个
实际未生效的可复现配置。[M5]

## 4. Parser 与证据状态机

parser 对真机格式执行以下结构验证：[M4]

- PER：概率密度函数声明、17 列表头、每行 zoom/field/frequency/azimuth/criterion/design
  与八个概率位列均可解析；位列只原样保存。
- MC：必须有 `Number of Monte-Carlo samples` 声明和五列表头；每行 sample/zoom/field/
  criterion/value 均解析，value 必须有限，sample id 必须完整覆盖 `1..N`。
- 文件缺失、同路径、编码/列数/数值/coverage 异常都返回封闭 enum `unavailable`。

解析成功也仍返回 unavailable，理由固定说明“PER 数值语义和 yield policy 未 ratify”。后续
available evidence 必须由独立 factory 接受 parser 产物、runner 证据、配置 provenance 和
ratified threshold 后派生，不能公开可随意填写的 dict/dataclass 构造器。

## 5. 良率统计口径：资深待 ratify 选项

推荐 **A：同一 trial 全场联合 all-pass**；备选 **B：只要求预先指定的关键场通过**；不推荐
**C：场加权平均**，因为平均会掩盖单场失效。选择必须在运行前写入配置 provenance，不能
看结果后改。[M7]

共同硬规则：

- 以 `(sample, zoom, field, azimuth, metric)` 绑定同一 trial；不得相乘边际通过率或跨 trial
  拼接。MTF 为 `value >= threshold`，RMS wavefront 为 `value <= threshold`。
- 首版推荐只接受 CODE V 已加权 polychromatic performance；若选择逐 wavelength，需另定
  export grammar、阈值与联合规则。
- 缺任一必需行、非有限值、值饱和且未由阳性对照证明有效、补偿器触限/丢弃或 trial 计算
  失败，都使整 run unavailable；绝不从分母删除坏 trial。
- N 在运行前按 two-sided 95% Wilson 区间目标半宽确定并锁定。保守规划可用
  `n >= 1.96²/(4h²)`：半宽 5% 约 385、3% 约 1068、2% 约 2401；最终 N、半宽和运行预算
  由资深 ratify。重复 run 分开展示，不事后随意合并。

## 6. 补偿器与量产装调假设

输入除 compensator commands/provenance 外，必须记录 `assembly_assumptions`：装调顺序、
可调自由度、行程/分辨率、成本档、field weights、group/label、WTF、SVD/MCP 策略。[M8]
真机 listing 未显式列出缺省补偿器，因此当前缺省行为标为 **未知**；需对照
`Tolerancing.pdf` 或下轮真机采样取证。后续 available gate 必须核验实际使用/被 SVD 丢弃的
补偿器、limit-hit、range 与批准配置一致；否则 unavailable。

## 7. 真机阳性矩阵与交叉核验

矩阵必须同时包含优化后已知好候选和当前 baseline 差候选，证明 TOR 输出有区分力，而非
只证明命令能跑。[M6]

1. 官方/已知好 lens 用最小 TOR 得到 listing 阳性，逐字段核对 listing 与 PER export。
2. 复验 B1/B2 双 buffer 单 GO，并注入预置 buffer、预置目标文件、同路径与导出失败，排除
   stale/覆盖。
3. NTR 取 7/11，核验 MC 行数、sample id 和 field coverage。
4. 缺省 TAN 90 与显式另一 AZI 双跑；RMS（无 FRE）与 MTF（有 FRE）双跑。
5. PER/MC 一致性检查：固定 design/sequence digest、metric、FRE/AZI、zoom/field 集一致；
   PER design 对 listing nominal，MC criterion/field coverage 对 PER。PER 概率位列与 MC
   分布统计只在手册语义钉死后才做数值交叉核验，当前不得猜。
6. 英语 ASCII 与非英语 Unicode 环境分别采样，编码证据入 fixture metadata。

## 8. 报告展示约束

proxy 与 TOR 不放在同一数值列：页面分成“制造性 proxy（原单位）”和“TOR 公差证据
（yield/CI，若 available）”两个视觉区，标题、单位和色阶独立，之间固定显示“不可直接
比较”。proxy 禁用百分比/yield 色阶；TOR unavailable 显示原因，不得渲染为 0%。[m3]

报告必须携带 engine/version、设计/sequence/raw-file digest、run id、耗时、metric/FRE/AZI、
field/wavelength 口径、N、tolerance/compensator/threshold profile、装调假设和 measurement /
configuration 双轴 provenance。排序第一不等于合格，最终背书属于 `[EXPERT]`。
