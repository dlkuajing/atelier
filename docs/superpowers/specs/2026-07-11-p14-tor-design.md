# Phase 14 铲 1：CODE V TOR 真公差良率设计

## 1. 目标、边界与诚实不变量

目标是把 CODE V 11.5 的 TOR 公差分析接成离线、可审计的候选设计证据。本文只设计
批处理契约并交付纯字符串 builder 与 fail-closed parser 接口；不接 orchestration 主链，
不声称已经产出真良率。

硬不变量：TOR 成功且输出通过严格解析时 provenance 才能是 `codev-tor-mc`；现有几何/
材料可制造性估计始终是 `proxy`；缺许可证、超时、非预期退出、缺文件、schema/version
不符、解析失败或样本不足均为 `unavailable`。任何失败都不得把 proxy 填进真值字段。
AI/LLM 不生成或改写处方坐标、公差数字、补偿器数字，也不作“合格”判断。

## 2. 证据边界

本机一手证据为 `D:\CODEV115\doc\Tolerancing.pdf`（CODE V 11.5 Tolerancing
Reference Manual）：

- Chapter 1 “Generating Default Tolerances” 证明 `DEF TOL` 能生成默认表；手册同时说明
  具体默认会依赖诸如 test plate 的制造假设。这只能证明功能存在，不能证明它适合手机
  镜头量产。
- Chapter 2 “Defining TOR Output” 证明 `WBF PER` 把 performance summary 写入指定
  worksheet buffer，`WBF MC` 写每次 MC performance，`NTR` 指定试验数，buffer 可用
  `BUF EXP` 导出。
- Chapter 2 “Description of TOR Output” 证明 TOR 原生指标限于 RMS wavefront、指定频率/
  方位的 diffraction MTF、CEF、PDL；performance summary 含 nominal 与 mean+2σ 的
  `DESIGN PLUS TOLERANCES`，补偿器含 mean+2σ `COMPENSATOR RANGE`。
- 同章明确 TOR 的 MC 对 wavefront differential coefficients 的二次模型抽样，并不逐次
  扰动处方后重新分析。若需要物理逐次扰动，应使用 Chapter 3 `TOLMONTE`。因此本文的
  “真 TOR”是 CODE V 原生 TOR 统计模型的真输出，不得描述成全处方 brute-force MC。
- 手册列表样例给出 cumulative probabilities（含 50.0%、84.1%、97.7%、99.9%）和
  MTF performance summary，但本次未找到完整 `BUF EXP` 文件语法样例。本机 macro 目录
  搜索也未得到可作为该文件 grammar fixture 的完整官方样本。因此解析格式标为
  **待真机采样**，当前 parser 只返回 unavailable，不编造 fixture。

本文所有 `GO` 后 buffer 所属、连续两次 TOR output selection 的状态行为、退出码容许集，
均标为**待真机验证**；builder 把这些假设显式留在 sequence 中，便于排窗时逐项证伪。

## 3. 批处理链

建议接口：

```text
build_codev_tor_sequence(
  zmx/seq 输入,
  显式公差表命令 + provenance,
  显式补偿器命令 + provenance,
  metric = MTF@frequency 或 RMS,
  MC 参数（trials，未来加已验证 seed/distribution）,
  PER/MC 两个 BUF EXP 路径
) -> .seq 文本
  -> codev.exe /B（复用 codev_batch 的 timeout/license/进程回收）
  -> PER + MC 原始导出文件
  -> versioned strict parser
  -> tolerance-yield evidence
```

ZMX 输入复用既有 `IN CV_MACRO:ZEMAXOS_TO_CV`；原生 seq 输入应使用经真机验证的
`IN`/`RES` 分支，铲 2 实现前不把两者混成猜测。结果只能读 BUF EXP 文件，listing 只可
用于诊断，绝不刮日志得到成功数字。运行前删除同名旧产物；运行后要求文件 mtime/大小、
schema 与 run id 对应本轮，避免认领 stale 输出。

当前离线 builder 强制非空公差表、补偿器和 provenance；禁止静默发 `DEF TOL`。它生成
`TOR`、指标参数、`NTR`、`WBF PER/MC`、`GO`、`BUF EXP`。随机种子命令尚无一手证据，
即使数据模型预留 seed，也不发未经证实的命令。

## 4. 公差表来源决策

| 选项 | 证据与风险 | 结论 |
|---|---|---|
| A. CODE V `DEF TOL` | 手册一手证实存在；默认含 test-plate 等假设，但没有证据证明符合本项目塑料手机镜头、供应商工艺与成本档 | 仅用于工具链 smoke，不作量产默认 |
| B. “行业标准手机镜头公差集” | 本仓与安装手册中没有可审计、适用于目标供应链的统一数字集；拍脑袋写数字会伪造可信度 | 当前不可用；若取得标准/供应商 capability，需记录版本、单位、分布、适用面型与来源 |
| C. 项目/供应商 capability 表，由资深 ratify | 能绑定材料、注塑/模压、装调、测量方式、成本档和补偿流程；是真正量产问题需要的输入 | **推荐的生产路径** |

推荐采用双 profile：`codev-default-smoke` 仅验证命令/解析、醒目标“非量产公差”；
`expert-ratified-production:<version>` 才允许进入真良率报告。当前没有获 ratify 的数值，
故生产默认值明确为**待主公/资深 ratify**，系统不得自带貌似合理的数字。公差记录至少含
命令原文、单位、分布、surface/group、上下限、测量/装配假设、来源文档与审批人/时间。

## 5. 输出契约与良率定义

`ToleranceYieldEvidence` 建议包含：

- `status: available|unavailable`；`provenance: codev-tor-mc|unavailable`；独立 proxy
  对照对象使用 `proxy`。
- `engine/version`、源设计 digest、sequence digest、run id、耗时、公差 profile/version、
  补偿器 profile/version、原始 PER/MC 文件 digest。
- metric definition：`mtf` 时必须携带 frequency lp/mm、azimuth、field、wavelength/权重、
  阈值及阈值来源；`rms_wavefront` 时携带 wavelength、field、阈值及来源。不能把 RMS spot
  或任意 scorecard 分数冒充 TOR 原生 RMS wavefront。
- `nominal`、`design_plus_tolerances_mean_plus_2sigma`、每 field/zoom 的 performance；
  `compensator_ranges_mean_plus_2sigma` 及单位。
- `mc_trials_requested`、`mc_trials_parsed`、每 trial/field 的原始值或可追溯摘要；分布配置。
- `yield_numerator`、`yield_denominator`、`yield_fraction`。良率定义为：在**资深 ratify 的
  metric 阈值与聚合规则**下，通过的 MC trial 数 / 可解析 trial 数。CODE V 给性能分布，
  Atelier 的 threshold 才把它转成 yield；未 ratify 阈值不得出良率。
- 二项比例置信区间，推荐 two-sided 95% Wilson interval（算法与 confidence level 入契约）；
  这只是有限样本不确定性，不覆盖 TOR 微分模型误差。样本数不由 AI 定，初始值待资深按
  精度/时长 ratify；报告必须同时展示 N 和区间，禁止只给百分比。

多 field/azimuth 的 trial 合格聚合（all-fields pass、指定关键场、或加权）会显著改变良率，
必须作为 ratify 配置，不设暗默认。若 MC export 没有稳定 trial id 或无法证明各场属于同一
trial，禁止擅自拼接，直接 unavailable。

## 6. scorecard 接线（铲 2）

现有 `ManufacturabilityProxy` 是 TTL、片数、特殊高折射玻璃、非球面复杂度与 CRA 的代理，
强制文案已经声明“非真公差良率”。新增并列结构，不替换或改名掩盖它：

```text
manufacturability_proxy: { provenance: proxy, ...existing fields... }
tolerance_yield: {
  status, value, confidence_interval, metric_definition,
  provenance: codev-tor-mc | unavailable,
  failure_reason?, run_evidence?
}
```

注意 provenance 双轴：`measurement_provenance` 表示数字来源（`codev-tor-mc` / `proxy` /
`unavailable`）；`configuration_provenance` 独立记录 tolerance/compensator/threshold profile
（CODE V smoke default、expert-ratified、或 unavailable）。真引擎数字配未经批准配置，不能
因前一轴为真而看起来已具量产权威性。

状态机只允许：完整运行 + 严格解析 + trial coverage + ratified threshold => available；其余
全部 unavailable 并保留结构化原因。不得捕获异常后调用 proxy 填 `tolerance_yield.value`。
排序第一也不等于合格，scorecard 不新增 pass/fail；最终背书仍属 [EXPERT]。

## 7. 真机验证矩阵与 proxy 对照

orchestrator 排窗至少选 2 颗**已交付候选 ZMX**，建议一颗 wide、一颗 telephoto（若实际
交付集不含该组合，则如实记录可得组合，不换成 seed 冒充交付候选）。每颗固定设计 digest，
执行：

| Case | 公差 profile | 补偿器 | 指标 | N | 需核验 |
|---|---|---|---|---:|---|
| delivered-A | CODE V default smoke | 明示 | MTF@资深选频 | 小样 smoke | PER/MC buffer grammar、field/trial identity、单位、退出码 |
| delivered-A | expert-ratified v1 | ratified v1 | MTF@同频 | ratified | yield+95% CI、重复跑稳定性、补偿器范围 |
| delivered-B | 同上两档 | 同上 | 同指标 | 同上 | 跨结构解析与缺失场 fail-closed |

每行报告并列：candidate id/digest、proxy 原始字段（不转成伪百分比）、TOR status、metric/
threshold、N、yield、CI、compensator range、两条 provenance、原始文件 digest、失败原因。
“proxy vs 真值”是定性/排序对照：由于 proxy 当前不是良率百分比，不计算误导性的数值差。
额外故障注入：无 license、timeout、删 PER、删 MC、截断行、非数值、未知 schema、trial 数
不符、旧文件、非预期 field；每项必须得到 unavailable 且 proxy 仍仅在独立栏展示。

## 9. 铲 1 验收

- `codev_tolerance.py` 仅纯 builder + fail-closed parser，不接主链。
- 单测证明公差/补偿器必须显式、BUF EXP 路径存在、未知输出不产生良率。
- 真机取得官方/实测 buffer 样本后，先以原始 fixture + 来源 metadata 锁 grammar，再实现
  versioned parser、Wilson CI 与 batch runner；fixture 未取得前保持 unavailable。
