## 0. 一句话

**把手机镜头「出一版设计」这个动作自动化**：从结构化 spec 到四件套交付物，零人工介入，
一次运行覆盖多个独立需求，质量对标同规格专利原设计。

**什么情况算没做到**（任一条成立即未达成）：

1. 过程中需要人选 seed、人调参、或人工重试
2. 交付物缺件（四件套不全）
3. 异源打平率低于门槛
4. 第三方拿我们的 ZMX 复算不出我们报告的数字

## 1. 北极星（终极目标 = "完成"的定义，不是无限调优）

### 1.1 里子（内核能力 · 第一目标）

**输入**：结构化 spec（EFL、F/#、FOV、像高、TTL 上限、传感器型号、成本档位、片数上限）

**产出**：一个或多个候选设计，每个候选**必须同时**包含四件套，缺一不算交付：

1. **光学处方** —— ZMX 格式，可导入 Zemax / CODE V 独立复核
2. **像质指标** —— RMS spot、MTF、畸变、相对照度、场曲
3. **公差敏感度 + 良率估计** —— 同一张公差表同时施于候选与对照专利
4. **相对成本指数 + 片数/材料权衡** —— 由片数、材料牌号、非球面数量、口径厚度驱动

**验收标准**：见 §3 距离定义。核心是**异源打平率**——候选所用 seed 与对照专利**不属于同一
专利家族**时，候选在 RMS spot / MTF / 畸变上不劣于该规格专利原设计的比例。

> **为什么必须异源**：现流程是 `需求 → 匹配最近专利 seed → 优化 → 候选`。若 seed 就是拿来
> 对照的那颗专利，"不劣于它"是循环论证——起点就是它。**同源提升率**（同族时的指标改善）
> 因此降级为**内部诊断指标**，永不单独对外引用、永不作为达成证据，且必须与异源打平率
> 始终使用不同名称。
>
> **为什么公差是必需件而非加分项**：多产必然带来"谁来筛"的新瓶颈——一天出 20 版，人一版版
> 看，瓶颈只是从"出设计"平移到"筛设计"。而筛的依据就是公差鲁棒性：量产不了的第一轮就该
> 淘汰。公差是产能放大能够成立的**必要零件**。

### 1.2 面子（交付形态）

浏览器演示界面：自然语言需求入口、光路图、MTF/点列图、评估报告、导出包。
面向镜头/模组厂的工程团队与决策者，用于现场演示。

### 1.3 里子 ↔ 面子

**里子是第一目标，面子服务于里子、不能替代它。**

具体到本项目最容易走偏的一处：**自然语言入口属于面子，明确不进任何判据**。
设计师本来拿到的就是结构化 spec，自然语言不是他们的瓶颈；把 NL 理解的失败率混进北极星
数字，只会污染一个本来干净的可复算量。零介入的起点因此画在**结构化 spec**，不是自然语言。

## 2. 不可变约束（循环永远碰不得，不进任何迭代论证）

### 红线①（项目物理 / 安全红线）

- **CODE V 单实例**：并发启动 CODE V 会导致 license 冲突与运行产物互相污染
  （P18 批次已实证污染 job-0020/0021）。这是**生产安全类物理终闸**。

  **准入判据（2026-07-27 主公修订 v2.1）**：真机跑批前必须证明
  **`codev` / `codevm` 实例数为零**，且运行全程持续监控——**一旦出现第二个 CODE V 实例，
  立即中止并将该次尝试标记为 contaminated**。

  修订理由：原措辞要求"零 `runner`（含 competitor）"，实测中主公的 Codex app-server
  会持续派生带 `-m "not real_machine"` 的 pytest 竞争者，该条件在真实工作环境下几乎
  永不满足，把红线变成了永久闭门。真实风险只有一种——**某个测试漏标 `real_machine`
  从而启动第二个 CODE V 实例**，而运行时监控能直接覆盖它，比事前静态清场更贴合风险本身。
  P18 那次污染的机制正是两个 CODE V 实例互撞，不是 CPU 争用。
- 除此之外，本项目为纯软件产品，不直接驱动生产设备，无人身/资损类物理红线。

### 红线②（元层约束 · 固定条款，不可删改）

- AI 多方论证**只产"方向 / 目标修订建议"**；改不改**永远由主公拍板**；AI 绝不自主改北极星 /
  方向定义 / 红线。**主公 = 最终仲裁者。**

### 红线③（诚实边界 · v0.1 教训固化）

- **判据的口径可以现在定死，判据的数值必须等实测**。禁止先验拍任何门槛数字。
  v0.1 把每个阈值都定义成"须由资深 ratify"，而那个人不存在，于是全部阈值永久 null、
  整个体系无法启动。
- **不得设立任何"等待某个不存在的人签字"的推进节点**。

## 3. 距离定义（怎么知道离北极星多远 · 诚实拆分）

> **铁律**：任一真值段未闭合 → distance **永不显示"逼近天花板"**；代理指标绿不得掩盖真距离。

| 段 | 定义 | 测量方式（确定性来源） | 诚实边界 |
|---|---|---|---|
| **代理级 P1 · 产出能力** | 一次运行在 `N` 个独立需求上零介入产出 `M` 个完整交付物，耗时 `T` | 待建：批量编排跑批脚本 + 交付物完整度校验器 | 可绿，**但不代表真距离**。当前基线 Stage C `2 delivered / 46 blocked` |
| **代理级 P2 · 异源打平率** | seed 与对照专利不同家族时，候选 RMS/MTF/畸变不劣于原设计的比例 | 待建：异源跨规格对拍器（对照组 = 底库 442 颗真实设计） | 可绿，**但不代表真距离**。当前**零数据**，从未系统实测 |
| **代理级 P3 · 交付物完整度** | 四件套齐全率 | 待建：四件套校验器 | 当前只有处方 + 像质两件；公差良率（MC 饱和）与相对成本指数（模型不存在）均缺 |
| **代理级 P4 · 可独立复核** | 第三方用自己的 Zemax/CODE V 复算出我们报的每个数字 | 导出 ZMX + 数字清单，外部软件复算比对 | 可绿，**但不代表真距离** |
| **真值级 T1 · 客户侧采用** | 镜头/模组厂的资深光学设计师，在真实项目中实际采用我们产出的候选（而非仅表示"看着不错"） | 客户演示记录 + 采用/退回记录 | **当前不可测**。卡点有二：① 无客户接触渠道 ② 项目内不存在资深光学设计师，主公是最接近的判断者但不产生量产可用性结论 |

**P 段与 T 段的关系**：P1–P4 全绿 = **够格拿去给客户看**；T1 闭合 = **客户认了**。
两者不可互相冒充。在 T1 闭合前，任何材料不得表述为"已达成北极星"或"量产可用已验证"。

`[EXPERT]` 因此不是开发 gate，而是 **T1 段的度量对象**——它发生在客户侧，
项目内不存在任何等待专家签字才能推进的开发节点。

### 为什么这套代理指标不需要人类签字

**对照组是底库里已被工业界量产验证的真实设计**——它们"够量产"是既成事实，不需要任何人认定。

**公差表与成本模型的绝对值可以不准**：同一张表**同时**施加于候选与对照专利，
表错了两边一起错，**排序不变**。这直接解开 v0.1"阈值须由资深 ratify"的死结，
也是底库规模第一次有了非营销的硬功能——从"说服力素材"升级为**统计对照组**。

**外部佐证**：自动镜头设计 SOTA（OptiNeuro, arXiv 2510.09979）证明自身的方式就是
"RMS 对比人工参考设计 + 导入 Zemax 独立复核"，全程无人类专家评判
（九片 1.973~2.158 µm vs 人工参考 2.135 µm，自评 "comparable to manual designs"）。
**这是该领域已被接受的判据形式，不是为绕开专家而发明的。**

## 4. 反目标（明确不做什么 · 防范围蠕变）

- **严格杂散光 / 鬼像验证** —— 需 LightTools / FRED 非序列工具链，换工具不是换努力。
  OptiNeuro 亦将 stray light analysis 明列为 AI 不可替代项。不得通过相邻场景悄悄纳入。
- **AR 近眼显示 / 波导** —— 需 RCWA 物理光学，是另一门学科；ZMX 序列几何管线物理上覆盖不了。
- **试制支持 / 装配方案 / 产线问题排查 / 客户现场技术支持 / 专利撰写** ——
  这些是光学设计师岗位的真实职责（招聘 JD 实证），但不在本产品射程内，留给人。
  替代边界只到「出设计」这个动作。
- **全自动无人替代设计师大脑** —— 行业与学术前沿未解（Synopsys 官方工具亦只做
  "起点候选 + 人评估精修"）。写进北极星 = 够不着且踩可信度。
- **绝对成本报价（元/颗）** —— 项目没有任何一条真实报价数据，永远给不出。
  成本一律为相对指数。
- **把产能表述成"放大 N 倍"** —— 没有真实人类工时 baseline，倍数缺分母，一问即穿。
  产能一律写绝对能力（N/M/T）。倍数只可用于营销话术，不得进入任何判据、报告或对外数字。

## 附：为什么废掉 v0.1

v0.1（2026-07-13 起草）不是进度慢，是**定义上不可完成**：

1. **终点吊在一个不存在的人身上**。全套体系以资深光学设计师的 `[EXPERT]` 签字为终点，
   项目从未有过这个人，`[EXPERT]` 一次都没被填过。Gate D 不是"还没做"，是不可关闭；
   连带 holdout 密封、盲法、rater 名单、角色分离机制全部失去对象——没有人可供分离。
2. **发布链吊在 GitHub 不提供的 API 原语上**。`X-00A` 要求一个
   `acquisition→snapshot→admission→terminal` 的 provider-side merge lease；
   契约自述该原语不可得则 v0.1 永久 `BLOCKED_WAIT_EXTERNAL`。
3. **代价可测量**。13 棵固定树连续被独立审查拒绝，最近数轮拒绝理由已是"某 hash 路径同时
   承载两种对象类型"这类协议自洽性问题；同期全仓 `.py` 中 `north_star` **零命中**——
   24 天未落地一行实现代码。

v0.1 的机器并发安全认知（M-01~M-06：CODE V 单实例锁、启动面收口）是**真实工程需求**，
已升为本文件红线①，按普通工程 backlog 项重新引入，**须剥离其密码学签名链、外部证明者与
CAS 收据链**——需要的是一把可靠的锁，不是一套可证明的锁。
