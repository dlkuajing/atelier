# External Integrations

**Analysis Date:** 2026-07-03

## APIs & External Services

**LLM Relay (Primary Integration):**
- OpenAI-compatible relay station - All LLM chat and image requests funnel through one endpoint
  - SDK/Client: `openai` Python package (AsyncOpenAI + OpenAI)
  - Configuration: `OPENAI_API_KEY` + `OPENAI_BASE_URL` (default `https://api.openai.com/v1`, overridden to relay)
  - Models routed via relay (verified 2026-05-21):
    - `claude-opus-4-7` (PRIMARY_CHAT) - Wizard main dialogue, multi-step tool use, parameter JSON
    - `claude-sonnet-4-6` (FALLBACK_CHAT) - Rate-limit/unresponsive fallback, ~1/3 cost
    - `gemini-3.1-pro-preview` (PRIMARY_LONG_CONTEXT) - Long-form reports, multimodal image understanding (2M context)
    - `gpt-image-2` (PRIMARY_IMAGE) - Report cover image generation
    - `gemini-3-pro-image-preview-4k` (ALTERNATE_IMAGE_4K) - High-res image alternative (validation pending)
  - Known unavailable models tracked in `app/core/llm_relay.py::KNOWN_UNAVAILABLE` (was Anthropic channels 2026-05-21, recovered same day)
  - Source: `app/core/llm_relay.py` - Single source of truth, never instantiate OpenAI clients elsewhere

**Patent Search (Wave 2, not yet live):**
- Espacenet OPS (European Patent Office) - Patent retrieval API
  - Auth: `EPO_OPS_KEY` + `EPO_OPS_SECRET` environment variables
  - Crawler: `scripts/patent_crawler.py --source espacenet`
- USPTO PatentsView - Patent search (no authentication required)
  - Crawler: `scripts/patent_crawler.py --source uspto`

**Optical Material Data:**
- refractiveindex.info (CC0 license) - Refractive index database for lens materials
  - Used by: `opticalglass` package for material lookup
  - Integration: Embedded in dependency, no external call at runtime

## Data Storage

**Databases:**
- PostgreSQL 14+ with pgvector extension (Wave 2, not yet live)
  - Connection: `DATABASE_URL` environment variable (format: `postgresql+psycopg://user:password@host:port/dbname`)
  - Client: `psycopg[binary]` async driver + `pgvector` vector extension
  - Purpose: RAG vector store for patent embeddings (BGE-M3 embeddings)
  - Status: Infrastructure configured in `pyproject.toml`, not yet deployed

**File Storage:**
- Local filesystem only (no cloud storage integration)
  - ZMX optical design files: `data/zmx/` (39 .zmx files)
  - Optical case library: `app/data/optical_cases/index.json` (generated by `scripts/generate_cases.py`)
  - Seed corpus: Embedded in `app/core/rag/store.py::_SEED_PATENTS` (5 hand-typed patent abstracts)

**Caching:**
- Python runtime caching: `functools.lru_cache` used for:
  - Settings singleton: `app/core/config.py::_get_settings()`
  - LLM clients: `app/core/llm_relay.py::get_sync_client()`, `get_async_client()`
  - RAG store: `app/core/rag/store.py::get_default_store()`
- No external caching layer currently deployed
- Cloudflare AI Gateway optional (Wave 2): `CF_ACCOUNT_ID`, `CF_AI_GATEWAY_URL`, `CF_AI_GATEWAY_TOKEN` environment variables configured but unused

## Authentication & Identity

**LLM Relay Auth:**
- Single API key: `OPENAI_API_KEY` environment variable (sk-relay format)
- Credentials source: Owner-provided relay (replaces v1.1's per-vendor key approach)
- No user authentication in backend (stateless optical computation + LLM relay)

**Third-party Credentials:**
- Environment-based only (no OAuth, no multi-user auth)
  - Relay: `OPENAI_API_KEY`, `OPENAI_BASE_URL`
  - Patent OPS: `EPO_OPS_KEY`, `EPO_OPS_SECRET`
  - Cloudflare: `CF_ACCOUNT_ID`, `CF_AI_GATEWAY_TOKEN`
  - Observability: `LANGFUSE_HOST`, `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`

## Monitoring & Observability

**Error Tracking:**
- Langfuse (optional, Wave 2) - LLM trace + cost tracking
  - Configuration: `LANGFUSE_HOST`, `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY` environment variables
  - Status: Endpoints exist in schema but integration not yet implemented

**Logs:**
- Structured logging via `structlog` (JSON output)
- Configuration: `LOG_LEVEL` environment variable (default `INFO`)
- Lifespan events logged: `lumira_backend_starting`, `lumira_backend_stopping`
- Error logging in modules: `app/core/optical_engine.py`, `app/core/zmx_materials.py` use Python `logging` module

**Health Check:**
- Endpoint: `GET /health` → returns `{"status": "ok", "version": "0.1.0"}`
- Used by Fly.io container health probes (30s interval, 10s timeout, 3 retries)

## CI/CD & Deployment

**Hosting:**
- Fly.io (production) - Singapore region (sin)
  - VM: shared-cpu-2x, 2 vCPU, 2048 MB RAM
  - Uvicorn: 2 workers (matches vCPU count)
  - Auto-scaling: 1 machine always running (prevent cold-start 503), 2nd auto-stops idle
  - TLS: Force HTTPS, proxy headers forwarded by Fly front-door
  - Health check: `/health` endpoint every 30s

**CI Pipeline:**
- GitHub Actions (`.github/workflows/ci.yml`)
  - Trigger: Push to main, PR to main
  - Concurrency: Cancel in-progress jobs on same branch
  - Runner: ubuntu-latest, 45 min timeout
  - Steps:
    1. Checkout code
    2. Setup uv via `astral-sh/setup-uv` (with cache)
    3. Install Python 3.12
    4. `uv sync --frozen --group dev --group optical` (core + dev + optical libraries)
    5. Run `pytest -v` with placeholder LLM credentials
  - Environment: `OPENAI_API_KEY=ci-placeholder`, `OPENAI_BASE_URL=https://example.invalid/v1`, `CORS_ALLOWED_ORIGINS=http://localhost:3000`
  - Tests: 131 tests, all LLM calls mocked

**Docker:**
- Multi-stage Dockerfile:
  - Stage 1 (base): python:3.12-slim + uv binary + BLAS/LAPACK dev libs
  - Stage 2 (deps): `uv sync --frozen --no-dev --group optical` (dependency layer caching)
  - Stage 3 (final): Copy app + run uvicorn with 2 workers + proxy-headers
  - Image optimization: ~25MB for uv, separate optical layer for cache efficiency

## Environment Configuration

**Required env vars:**
- `OPENAI_API_KEY` - Relay authentication (format: sk-relay-*)
- `OPENAI_BASE_URL` - Relay endpoint URL (default: `https://api.openai.com/v1`, override to `https://api.openbili.com/v1`)

**Optional env vars (Wave 2 features):**
- `DATABASE_URL` - PostgreSQL connection (pgvector RAG)
- `EPO_OPS_KEY`, `EPO_OPS_SECRET` - Espacenet patent API
- `CF_ACCOUNT_ID`, `CF_AI_GATEWAY_URL`, `CF_AI_GATEWAY_TOKEN` - Cloudflare caching layer
- `LANGFUSE_HOST`, `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY` - LLM observability

**App config vars:**
- `ENV` - Deployment environment (local/production, default: local)
- `LOG_LEVEL` - Logging verbosity (default: INFO)
- `CORS_ALLOWED_ORIGINS` - Comma-separated allowed origins (default: http://localhost:3000)

**Secrets location:**
- `.env` file (gitignored, not committed)
- Fly.io secrets vault: `flyctl secrets set KEY=value`
- Production: Uses Fly's encrypted secret storage
