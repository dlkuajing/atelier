# 对照侧像质：报排名，不设下限（2026-07-30）

## 开放审计项

P2 的 par 裁决若对照本身就是颗差镜头，那条 par 没有说服力，而读者**看不出来**。
`.planning/evidence/p2-audit-open-items-2026-07-29.md` 第 9 条。

**绝对下限这条路已实测走不通**：唯一可复用的既有常量是 **50 lp/mm 处的 RMS 点列
半径**，而探针报的是 **100 lp/mm 处的直径**；首份闸后读数里那个 **97.97 µm** 的对照
**舒舒服服地落在它里面**。新造一个阈值 = 先验拍板。

## 做法：排名代替阈值

报**对照在一个点名参考总体里的百分位**。排名是无标度的，且对分布尾部免疫 ——
这里尾部不只是长，它伸到 **8.3e20 µm**。

读者拿到的是「这条 par 打赢的对照位于语料库 p85」，即 **85% 的参考总体成像更好**。
线由读者自己划。我们报数字，并**点名分母**。

## 参考总体（分母）

| | |
|---|---|
| 池 | `data/zmx` 的 442 颗在库案例 ZMX |
| 判据 | 无 CODE V 报错 **且每一个声明视场都出了正的逐视场 SPOTDATA 读数**（`n_positive == num_fields`） |
| **n** | **218** |
| 量 | 跨视场取最大的 CODE V RMS 点列**径**（µm，是直径不是半径） |
| 来源 | `trace-census-20260728/perfield-census.jsonl`（sha256 记在产物里） |

**全视场覆盖筛不是装饰**：`@rmssum` 跳过追迹失败的视场、在幸存者上取最大值，
所以部分追迹的案例报出的数**比它应得的小**。放进来会让参考总体在**最要紧的地方**偏乐观。

**仪器同一性**（不是近似，是同一次调用）：census 的逐视场值是
`SPOTDATA(1,f,1,0.01,'CEN',0,0,^spot)` → `^spot(1)`（mm），正是 `@rmssum` 在 `*1000`
之前的逐视场操作数 —— 同一调用、同一数组下标。手工对过：`census.jsonl` 的
`rms_spot_um` 恰等于 `perfield-census.jsonl` 里最大逐视场项的 1000 倍。

## 四条必须随数同行的告示

1. **重尾**，最大值不是物理上有意义的点列尺寸 —— 用排名，别用跨度。
2. **这个池是 `data/zmx` 的可追迹子集，不是 P2 合格对照总体**（后者还要过保真度
   与产品自身参数闸）。它更宽、更宽容，因此**这里的百分位偏保守地低估对照之弱**。
3. **全视场覆盖不等于物理合理**：有一颗每个视场都"追迹成功"却读出 8.3e20 µm，
   而它在 `index.json` 里存的 `image_height_mm` 是 **5.9e17 mm**。
4. **只有 RMS 点列**：census 不含逐视场 MTF / 畸变，所以另两项 P2 判据**不提供百分位**。

## 顺带发现（另开工单，不在本铲范围）

`index.json` 里有 **13/442** 行的 `image_height_mm` 落在 0.1–30 mm 之外：
`US-11719917-B2-e6` 是 **5.9e17 mm**，另外 12 行在 40–52 mm。
手机镜头像高不可能是 40 mm 以上，这批要么是数据缺陷、要么是单位混用
（与 `project-fov-deg-unit-mix` 同一类病）。**自指式合理性判据因此失效**：
用「点列径是否超过该镜头自身像高」筛，218 颗里只筛出 1 颗，
因为坏案例的像高**和它的点列径一起坏了**，方向相同。

## 复算

```
uv run python scripts/corpus_quality_distribution.py --check --census <perfield-census.jsonl>
uv run python scripts/corpus_quality_distribution.py --rank 97.97
```

`--check` 需要那份 runtime census（不在 worktree 下），所以它是本地闸而非 CI 闸；
产物自带 census 的 sha256，用于确认是哪一份字节。
