## 三、⚠️ EFL 改用 receipt 的实算值——初版用尾注推导是错的

**初版写的是「EFL 从文件自己的尾注推，刻意不走 receipt（已知 9 处错位）」。
合并前对抗审查指出两个问题，都成立：**

1. **那是「声明 EFL」不是「实算 EFL」**。`ATELIER_FTAN_IMH_SANITY_MM` 回溯到
   `prescription.focal_length_mm * tan(hfov)`——专利表**声明**的焦距；
   而语料侧 `index["efl_mm"]` 是 Optiland 从面型**算出来**的。
   同一道可达性闸两把尺子，且分歧方向是 **fail-open**
   （`seed_efl_is_reachable` 在 seed EFL 偏大时放行）。
2. **推导只有约 80% 准**。拿 receipt 当真值实测：**462/581 在 ±1% 内**，
   最坏高估 **2.817×**（`US-10514523-B2-e6`，推导 2.411 / 实算 0.856）。

**改成 receipt 的 `worker_response.efl_mm`** —— 那正是 Optiland 算出来的焦距，
与语料侧同量。**错位风险不适用**：join 走的是 receipt 自己写下的 `published_zmx_path`
（那次尝试实际产出的文件），不是 `{patent}-e{N}` 键猜测。
实测覆盖：**205/205 全部走 receipt，零回退**（产物 `efl_source` 字段可查）。

⚠️ **换源还静默放宽了一道闸，已披露（第二轮审查抓的）**：`read_first_order` 在半场 ≥85° 时
拒绝推 EFL（`tan` 不再是可用除数），所以这类行原本从 `first_order_not_derivable` 出局。
receipt 的 EFL **不需要正切**，于是它们开始悄悄进池——**12 颗，其中 11 颗达标**，
**这正好就是 80 → 91 那个「池子更大」**。它们是真实超广角（全场 170–176°、
声明像高 1.65–3.58 mm 对 EFL 1.09–2.40、RMS 0.69–6.45 µm），**不是垃圾**；
但它们全是 LARGAN，而且对 `served` 的贡献是 **0**（12 档口径逐项未动）。
⇒ **「池子更大」不是收益**，产物已新增 `receipt_admitted_past_the_tangent_guard` 计数。

⚠️ **join 的第一版是不确定的，已修**：basename 在多次 attempt 之间**会重复**——
610 个 basename 里 **107 个有多份 receipt、12 个的 EFL 值不一致**（最大分歧 **0.174%**，
全是同一批续案的 4 个实施例）。第一版在 glob 循环里直接赋值，等于**按文件系统顺序取最后一个**，
换台机器重算就可能不同——而这份产物正靠「重算必须一致」的测试背书。
现在改成：收齐全部读数 → 分歧超过 **1%** 就**丢弃该文件**（说不清是哪次 attempt 产出的）→
否则取确定性的 `min`。今天 **0 拒绝**，池子不变，产物新增 `receipt_join` 记下这四个数。

### 自检也一并修了：初版只验索引前 200 行

`check_derivation` 默认 `index[:200]`，而索引**按 intake_batch 排序**——
那 200 行里 **DATA-10b 零覆盖**，而推导恰恰在 DATA-10b 上只有 **22/75 = 29%** 命中。

| 切片 | n | ±1% 内 |
|---|---|---|
| `index[:200]`（初版报的） | 153 | 146 = **95.4%** |
| **全索引（现在报的）** | **393** | **318 = 80.9%** |

产物现在带**逐批次**明细（DATA-09d1 173/184、DATA-06c 57/59、**DATA-10b 22/75**、
P12-4B 1/6），并且**不再有任何通过率断言**——那只会把今天的语料构成写死成阈值；
测试改为钉住「逐批次差异必须仍然可见」。初版产物记着的 `min 0.2657`（差 3.8 倍）当时没转述，现在写在这里。

## 四、诚实边界（每条都可能让上面的数字缩水）

1. **「与语料零重叠」只在文件名层成立。** 按 `prescription_identity` 的行集合语义：
   语料 442 文件 = **354 个处方**、staging 613 文件 = **496 个处方**，
   **两池共享 49 个处方**（68 个 staging 文件 / 64 个语料 case）。
   落到本页的健康件上：57 个处方里 **19 个 `data/zmx` 已经有**，
   ⇒ **真正新增 38 个**，不是 57。测试只比了文件名，措辞已按此更正。
2. **这是「池子里有没有」，不是「打分器会不会选」。** `rank_seeds` 按参数邻近度选，
   不按 RMS 选；本页的 `served` 是**可行性**上界。真正的收益要等把 staging 并进
   case library 之后重跑配对才知道。
3. **视场上限 20° 目前不在流水线里**，是本页提出的约束。今天的 `preferred` 池只按
   「可达 ∧ 质量」筛，不看视场——这正是「放开 screen 3 会选到差 43.9° 的 seed」的成因。
4. **并进来要走 ingest，不只是改一个筛**：staging 颗粒没有 `index.json` 记录、
   没有逐案 JSON，`cases_for_scenario` / `rank_seeds` 现在看不见它们。
5. **独立样本没被这条解决。** 若按「挑 RMS 最低的」贪心选，50/59 会落到同一件专利
   （SAMSUNG `US-12560782-B2`）。**但池子本身是有分散度的**：每对照可选
   **不同处方**中位 9、最多 28、只有 3 个对照零选项。分散度要靠选择规则去兑现。
6. 有几颗健康件的一阶量看着可疑（如 APPLE 两颗 EFL 0.56 / 0.84 mm 而视场 72–75°）。
   **并库前必须逐颗过像高闸与一阶自洽性**，不能因为 RMS 好看就放行——
   这正是 `data/zmx` 那 8 颗发散件混进来的方式。
7. 读数来自 2026-07-28 的 staging 普查；产物记了 census / index / quarantine 的 sha256。
   **staging ZMX 自那以后是否变过没有验**。

## 四点五、可行性已实测：12/12 能建出来，但会**继承那把坏尺子**

并库最可能失败的一步是「`build_sample_from_optic` 根本建不出来」——语料里已知至少一颗
会在 builder 里挂死，所以 `generate_cases.py` 每次 build 都套 90s 守护线程。
拿当时那批健康非 LARGAN 里 RMS 最低的 12 颗实跑（同样的 90s 超时隔离；
**探针跑在 EFL 换成 receipt 之前的池子上**，结论是「builder 通不通」，不受换源影响）：

| | |
|---|---|
| 结果 | **ok 12 / timeout 0 / error 0** |
| 尾注推导 EFL vs builder 实算 EFL | 中位 **1.0001**（区间 0.9871–1.0035） |
| 场景分类 | wide 6 / telephoto 4 / ultrawide 2，无异常 |

⇒ **并库这一步是通的，不需要新工具。**

⚠️ **但同一次探针也复现了那把坏尺子**：12 颗**全部** `mtf_max_field_frac = 0.5`，
存量 Optiland RMS 直径 / CODE V 全场直径 **中位 0.384**（区间 0.175–1.179）。
也就是说，**照现状并库 = 再往语料里放几十颗带同样系统性低估的记录**，
而产品侧路由闸 `_SEED_ROUTING_MAX_RMS_UM = 100.0` 读的正是这个被低估的量。
⇒ **并库必须与「像质换成同一把尺子」同批做，否则是在放大 PR #159 记的那个缺陷。**

另：`US-20170090155-A1-e1` / `US-9897779-B2-e1` 被推出 EFL **0.566 mm** 却分到
`smartphone-wide`。0.57 mm 焦距不是手机主摄。**并库前这类必须逐颗过一阶自洽闸**，
不能因为 RMS 好看就放行——`data/zmx` 那 8 颗发散件正是这么混进去的。

## 四点六、用「打分器会挑谁」重算一遍：质量解决了，独立性没有

第四节的 `served` 是**可行性**（池子里有没有），不是**打分器会不会挑到**。
用 `rank_seeds` 的主导权重做代理（fov 0.46 / efl 0.20 / fnum 0.05，按各自量纲归一），
在「异源 ∧ 可达 ∧ ≤20° ∧ ≤语料中位」的 175 颗合并池上逐对照挑一次：

| | 今天生产线实际挑到的 | 代理打分器在合并池上挑到的 |
|---|---|---|
| 被选 seed 的 CODE V 全场 RMS 中位 | **101.27 µm** | **4.69 µm**（区间 1.53–8.75） |
| 59 个对照都挑得到吗 | 是（但靠 fallback 到 `reachable`） | 是（59/59 全在质量闸内） |
| **落在几件不同专利上** | 6 | **6**（49/59 落在 `US-12560782-B2` 一件上） |

⇒ **起点质量提升 21.6 倍，独立样本一点没动。**
staging 解决的是「候选从一颗 101 µm 的烂镜头出发」，
**不解决**「41–49 条 trial 共用一颗 seed」——后者要靠选择规则（比如同一 seed 的使用次数上限）
或更多异源处方，不是靠这批料。**引用 P2 打平率时这两件事必须分开说。**

⚠️ 这是**代理**不是实跑：真 `rank_seeds` 还看像高 / 片数 / TTL / 质量惩罚，
且在池内做归一化。「6 件专利」是量级指示，不是精确值。
