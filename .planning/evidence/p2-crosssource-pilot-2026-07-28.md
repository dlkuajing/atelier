# P2 异源打平率首测 · 先导（2026-07-28）

**一句话**：北极星主指标第一次真机端到端跑通，**首个诚实读数 = 0 打平 /
5 条可判定 / 24 条 trial**；过程中查出**三个缺陷**，其中一个让我们交付的候选 ZMX
**不是我们量的那个设计**。三个都已修，修后重测仍 0 打平。

**当前挡在 P2 前面的不是配对协议、也不是样本量，而是产出能力本身（北极星 P1）**：
24 条里 19 条（79%）根本判不了。而在交付物忠实、能判的那 5 条上，
候选 RMS 点列比对照专利差 **1.7×–50×**，**一次都没打平过**。

**北极星 §0 判「没做到」的第 4 条正是这个形态**：
「第三方拿我们的 ZMX 复算不出我们报告的数字」。

## 0. 这一铲做了什么

`.planning/NORTH-STAR.md` §3 把异源打平率列为主指标并记「当前**零数据**」。
前两铲备齐前置数（#99 样本量、#104 对照侧像质基线），剩下的卡点是**对拍器不存在**。
本铲建了对拍器 `scripts/p2_crosssource_trial.py` 并**在同一铲里用它跑批**
（不留 ahead-of-consumer 的件）。

一个 trial 的口径：

1. 取一颗通过全部资格闸的**对照专利原设计** `C`
2. **spec 取 `C` 自身处方**（EFL / F# / 像高）——`C` 按构造就是满足该 spec 的设计
3. 路由一颗**异源** seed `S`（`p2_pair_census` 的保守品牌桶，argmin）
4. 走生产 `run_codev_target_standard(emit_optimized_zmx=True)` 优化 `S` → 候选 ZMX
5. **同一探针、同一组设置**量候选与对照（探针复用生产 `_metric_function_block`）
6. 「不劣于」= 低优指标 `<=`、高优指标 `>=`；三项全过才算该 trial 打平

**门槛数值一律留空**（红线③）。「不劣于」是口径不是数值，故可判；
「多少打平率算达成」不在本文出现。

不可判定的 trial **一律留在分母里**，绝不丢弃——丢弃的方向恒是把主指标推高。

## 1. 缺陷一：候选 ZMX 的文件名挡住独立复核

`_target_optimized_zmx_filename` 用 `f"{efl:.6g}"` 拼出
`..._target5.68024_vig0600_optimized.zmx`——正是 `codev_optimize.
_fmt_edge_filename_token` 早已记录并为渐晕 token 修过的 CODE V 危险文件名形状
（小数点后跟数字、同一点分段内还有非数字内容）。

当时**刻意不守卫**，理由写在注释里：「它由 zmx_writer Python 侧落盘、
不经 CODE V 打开」。**该前提已不成立**——候选 ZMX 是交付物，
北极星 P4 要求第三方导进 CODE V/Zemax 独立复核，P2 也必须重新导入候选才能量它。

### 真机单变量 A/B

同一份字节、同一文件名长度，只把 stem 里的 `.` 换成 `x`：

| arm | 文件名 | 结果 |
|---|---|---|
| A | `..._target5.68024_vig0600_optimized.zmx` | `ERROR - Zemax File ...`，导入**空系统**（EFL 1e+35 / NUM W=1 / NUM F=1 / 全零度量） |
| B | `..._target5x68024_vig0600_optimized.zmx` | 正常（NUM W=3 / NUM F=2 / EFL 4.507） |

**仓库内留存的 4 颗历史候选 ZMX（`.planning/loop/candidates-2026-07-09/`）
全部是带小数点的命名。**

**与缺陷二的交叉核对（旗舰候选只中一条，不是两条）**：这 4 颗的 seed
`US20170003482A1` / `US20170045714A1` 均为 **`EVENASPH`-only**（15 / 16 面，
`XDAT=0`），其候选也**完整保住** 15/15 与 16/16 面非球面。
即旗舰候选的**处方结构完好**，只是**文件名打不开**——两个缺陷各中一条，
不叠加。

**改法取根因**：EFL token 改为微米定宽整数（`_target005680`），
并对 `optimized_zmx_out` 施加 `ensure_buf_exp_safe_filename`；
该守卫 docstring 原本明确建议豁免这个文件，一并更正为
「按文件用途判断，不按它当前有没有调用方」。

## 2. 缺陷二：候选处方被悄悄剥掉全部非球面（更严重）

trial `US-11846759-B2-e8`，seed `US-12124006-B2-e2`：

| | 值 |
|---|---|
| CODE V 会话内 `aut_converged` | **1**（EFL 偏差 5e-09%） |
| 会话内 `post_aut` RMS 点列 / 波前 | **60.8 µm / 3.15 波**（系统在会话里追迹正常） |
| 重新导入候选：EFL / F# / 像高 | 1.83612 / 1.83 / 4.12399 —— 与会话内**逐位一致** |
| 重新导入候选：NUM W / NUM F | 3 / 2 |
| 重新导入候选：RMS / 波前 / MTF / 畸变 | **全部塌回累加器种子值 → 全部 withheld** |

纯文件比对（**不需要 CODE V**）：

| | 面型 | XDAT 行 |
|---|---|---|
| seed `US-12124006-B2-e2` | 5 `STANDARD` + **12 `XASPHERE`** | **204** |
| 交付候选 | **17 `STANDARD`** | **0** |

**12 面非球面被整体剥掉。** 交付的是一颗全球面镜头，不是我们量的那个设计。

### 根因：两个自家模块之间的字符串词汇缺口

1. Zemax `XASPHERE` 导入 CODE V 后 `(TYP SUR)` 返回 **`SPS ODD`**（奇次非球面）
2. `codev_readout` 把十个系数初值设 0，**只在 `^surf_type = "ASP"` 或 `"CON"`
   时填充**（`codev_readout.py:279`）——`SPS ODD` 两支都不匹配，十个系数原样留 0
3. **0 恰好就是「这面是个球面」的读数**
4. `zmx_writer._zemax_surface_type` 看到「无偶次项 + 不认识的类型」→ 回落 `STANDARD`

讽刺的是 `zmx_writer` 本来就认 `"XASPHERE"` 字面量——但 readout 从不发它，
发的是 CODE V 的 `"SPS ODD"`。而 readout **同一条记录里就带着 `surface_type`**，
判别所需的信息一直在，只是被丢掉了（与保真度审计里 `finite_final_rays`
被量出来又丢掉是同一形状）。

### 这是本仓库第 7 例「退化值等于良性读数」，也是第一例出现在**输出侧**

前六例（`@rmssum` 起始 0、`@mtfmin` 起始 1.0、`@lcum` 单波长恒 0、
`SPOTDATA` 轴上 0.0、指标宏全套种子值、点列径 1e+20 朝 +∞ 跑）全在**读数侧**。
这一例在**写出侧**：读不懂的面型被写成一个看起来完全正常的球面。

### 影响面（按 BOM 解码、`.zmx`+`.ZMX` 全枚举）

| 池 | 文件数 | 含 `XASPHERE` | 占比 |
|---|---|---|---|
| `data/zmx` | 442 | **158** | **35.7%** |
| `data/zmx-staging/patent-local-replay` | 613 | 266 | 43.4% |
| `data/zmx_staging_p12` | 18 | 7 | 38.9% |

### 先导内的正负对照（同一批、非单向观察）

| seed 面型 | n | 候选面型 |
|---|---|---|
| `EVENASPH`-only | 5 | **全部保住**（12E→12E ×4、12E→12E） |
| `XASPHERE`-only | 4 | **全部归零**（12X→0、14X→0、8X→0、8X→0） |
| 混合 16E+2X | 1 | 16E 保住、**2X 丢失** |

结论的依据是**源码里定位到的确定性机制**，不是这 10 例的统计一致
（小样本完美一致在本项目已三次被证伪，故不以样本量作论据）。

### 方向性后果与语料保真度缺陷**相反**

保真度缺陷（PR #98）把主指标**推高**（对照更差 → 更容易打平）；
本缺陷把主指标**压低**——先导里 `US-12092797-B2-e1` 判 `worse`、
候选 RMS **1080.88 µm**，输在我们交付了一颗去非球面的镜头，不是输在设计能力。

**两个缺陷方向相反，不能互相抵消着解释——必须分别修。**

### 改法：fail-closed，不猜

`_zemax_surface_type` 对无法忠实表达的面型改为 `ValueError`（报出面号与类型）。
允许表取实测词汇（先导 readout 实际出现 `SPH` 140 / `ASP` 332 / `SPS ODD` 72）
加既有 ZMX 拼写。`run_codev_target` 的重建本就 fail-open 并记 `zmx_rebuild_error`，
故调用方如实报「没有候选」，而不是交付一颗不是我们量的镜头。

**明确未做**：没有去读 odd asphere 的系数，也没有决定它在 ZMX 里的表示。
本铲只把「悄悄错」变成「响亮地失败」。读回 odd asphere 是独立一铲，
也是**当前挡在 P2/P3/P4 前面最上游的一件事**。

## 3. 缺陷三：autovig 因 rung-0 超时整条放弃（3/24）

先导里 3 条 trial 根本没拿到候选，`blocked_at = optimize_no_preferred`、
两配置均 `kind=timeout`，且三条 elapsed **精确同为 360.3s**（= 2 × 180s 硬超时，
到 0.1s 一致）——**这个巧合本身就是判据**：不是"设计难优化"，是编排在固定处放弃。

根因写在 `run_codev_target_autovig` 自己的 docstring 里：`num_fields` 从 rung-0
那次 run 学，rung-0 自己超时就无从学起，于是搭不出任何更高 rung。
逃生口也在同一段——注入 `num_fields`。`run_codev_target_standard` 本来就收这个
参数，缺的只是调用方去读。新增 `zmx_import_prep.declared_field_count`（FTYP j4），
离线读、零 CODE V 调用；**阳性对照**：对先导中拿到对照读数的 14 条 trial，
离线声明值 vs CODE V 自己的 `(NUM F)`，**14 match / 0 mismatch**。

## 4. 先导结果（修复前，n=24）

跑批目录 `D:/atelier-stagec-runs/p2-pilot-20260728/pilot24/`（仓库外）。
24 个 trial 按 control_case_id 排序后**等距抽样**自 167 个可成立异源 trial，
**非随机**。用到 **16 颗不同 seed**。

**红线①**：跑批前 0 会话、跑批后 0 会话（判据 = 父进程非 codev/codevm 的实例数）。
总耗时 2203.5s，单 trial 中位 **56.3s**。

| 判定 | 数 |
|---|---|
| **par（打平）** | **0** |
| worse | 7 |
| spec_not_met（EFL 未达 target） | 4 |
| unmeasurable | 13 |
| **合计** | **24** |

| 口径 | 值 |
|---|---|
| 打平率 / 全部 trial | **0.0%（0/24）** |
| 打平率 / 仅可判定 | **0.0%（0/7）** |
| 打平率 / 仅无渐晕裁剪 | 0.0%（0/7，7 条可判定全部 edge=0） |

逐指标（仅可判定的 7 条）：**RMS 点列 0/7**、MTF 3/7、畸变 2/7。

### 可比性已核（否则整个数字无效）

`@rmssum` / `@mtfmin` 都按 `1..(NUM F)` 逐视场循环，两侧视场数不同就不可比。
实测：7 条可判定 trial **全部**候选 2 视场 vs 对照 2 视场、3 波长 vs 3 波长。
全库仅 1 条视场数不匹配（`US-12345855-B2-e2`，3 vs 2），而该条本就 `unmeasurable`，
从未进入比较。**0/24 不是视场数错配造成的**。

### ⚠️ 这个 0.0% **不是有效的 P2 读数**

它是在**已知有缺陷的交付物**上量出来的：`XASPHERE` seed 的候选被剥了非球面
（见 §2）。修复后重测见 §5。

### 但有一条不受该缺陷影响，且方向明确

**`EVENASPH` seed 的交付物是忠实的**（非球面完整往返），而这些 trial **5/5 全输**：

| control | 候选 RMS | 对照 RMS | 倍数 |
|---|---|---|---|
| `US-20240168263-A1-e10` | 42.41 | 4.566 | 9.3× |
| `US-11933948-B2-e12` | 52.84 | 4.347 | 12.2× |
| `US-12259531-B2-e11` | 7.764 | 4.525 | **1.72×**（最接近的一条） |
| `US-20240176104-A1-e2` | 283.1 | 7.764 | 36.5× |
| `US-20220187578-A1-e8` | 758.9 | 15.24 | 49.8× |

**候选一次都没在 RMS 点列上打平过（0/7）**，在交付物忠实的子集上也是 5/5 输，
差距 1.7×–50×。这不能归因于任何一个本文修掉的缺陷。

### MTF 子结果不可采信（探针已知漏洞，如实标注）

MTF 打平 3/7 与 RMS 全输并存，物理上可疑。机制上有洞：`@mtfmin` 只在
`^xmtf >= 0 and ^ymtf >= 0` 时更新，**MTF 计算失败的视场被静默跳过**，
于是最小值可能只取自视场的一个子集。`@rmssum` 有同形状的洞（`^err = 0` 才更新），
但它的方向是让 RMS **偏好**——0/7 是在这个偏好之下仍然全输，故 RMS 结论更硬。
本轮**未记录逐视场 MTF**，无法从现有数据判定 3/7 里有几条是跳过造成的。
**不以 MTF 子结果作任何论据。**

### 71% 的 trial 连判都判不了

`unmeasurable` 13 + `spec_not_met` 4 = **17/24（71%）**。
拆开：`aut_not_converged` 4、`optimize_no_preferred` 3（即缺陷三，已修）、
其余为候选或对照的实光线度量塌回种子值。

**这说明当前挡在 P2 前面的不是配对协议、也不是样本量，而是产出能力本身**——
北极星 P1 段。

### P2 的第一个诚实读数

### ⚠️ 对我自己上一条结论的更正

我此前写下「那 3 条 360.3s 是编排在固定处放弃，**不是设计难优化**」。
注入 `num_fields` 后的实测**推翻了后半句**：

| control | 修复前 | 修复后 |
|---|---|---|
| `US-20210389571-A1-e2` | 360.3s / `optimize_no_preferred` | 796.6s / **`spec_not_met`**（产出了候选，但没达 spec） |
| `US-20220011544-A1-e5` | 360.3s / `optimize_no_preferred` | 1116.7s / `unmeasurable`（产出了候选，度量被扣留） |
| `US-12468127-B2-e11` | 360.3s / `optimize_no_preferred` | **2522.0s**（≈14 × 180s，爬满 7 rung × 2 配置）/ **仍 `optimize_no_preferred`** |

**准确说法**：注入确实拆掉了一道人为天花板，**3 条里 2 条得以继续往下走**；
但**没有一条因此变成有效测量**，而第 3 条只是花 42 分钟证明了它在
180s/rung 的预算下**是真的跑不出来**，不是被编排冤枉的。
代价是整批墙钟 2.5×。→ **需要 per-trial 墙钟预算**，否则全量跑批不可控。

## 6. 未做 / 未验证（明说）

- **24 条为等距抽样、非随机**；167 个可成立 trial 只用到 16 颗 seed
  （全库上限也只有 31 颗，见 `p2-pair-feasibility-2026-07-28.md`）。
  **有效样本量远低于 24，不得按独立样本报置信度。**
- **没有读 odd asphere 系数**，只把「悄悄错」改成「响亮地失败」。
  这是当前挡在 P2/P3/P4 前面**最上游**的一件事。
- **没有改 `run_codev_target_autovig` 本身**在 rung-0 超时后自取 `num_fields`；
  本铲只在调用方把已有参数填上。
- **未记录逐视场 MTF / RMS**，故 §4 的 MTF 子结果无法自证。
- **渐晕不对称未消除**：autovig 裁的光瞳会写进候选 ZMX，使候选口径可能比对照窄
  （方向推高主指标）。本轮 7 条可判定 trial 恰好全是 `edge=0`，故未受影响，
  但这是运气不是设计。分层口径 `par_rate_unclipped_only` 已就位。
- **相对照度与场曲未测**（四件套「像质指标」仍差这两项）；公差良率与相对成本指数
  两件套完全未动。
- **打平率门槛仍留空**（红线③）。本文不给任何"多少算达成"的数值。
