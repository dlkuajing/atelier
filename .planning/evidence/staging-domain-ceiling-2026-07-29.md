# staging 池域内规模：**41/88 判得动的里域内命中 46.6%**（2026-07-29）

> ⚠️ **本文件是对同名前一版的更正。** 前一版写「staging 最多补 40 颗、合计 95、
> 不到翻倍」，据此推出「提升 staging 价值有限、不如按域重采」。
> **那两个数都是错的，而且方向相反地错**——详见文末「更正记录」。

## 逐格摊开（不靠推理，直接数）

| staging 池 613 颗 | 数 |
|---|---|
| ① 严格可追迹 | 238 |
| ② ∧ 保真度干净 | **205** |
| ├ 有 receipt，判为**域内** | **41** |
| ├ 有 receipt，判为域外 | 47 |
| └ **无 receipt，无法判** | **117** |

**可判子集命中率 = 41 / 88 = 46.6%**

按此比例外推 205 颗 → **域内约 96 颗**。⚠️ **外推，未验证。**

## 「按域采」的建议还成不成立

**部分成立，但支撑它的数字要换。**

真正的依据是：可判子集里 **47/88（53.4%）转出来落在产品域外**。
一半以上的转换产出用不上，这本身值得在采集/转换阶段加域筛。

**但前一版用「只剩 19.5%」来论证紧迫性，那个比例是错的**（分母用错，
详见更正记录），**不能再引用**。

## 未做 / 未验证（这些决定了 96 准不准）

- **117 颗无法判**是 key 构造覆盖不全所致，**不是数据缺失**。
  receipt 里的 `embodiment` 至少三种形态：`'1st Embodiment'`、
  `'Ability weatherproof optical image capturing system first embodiment'`
  （序数词在**句尾**）等。把匹配补全才是真数，**96 只是外推**
- **未含 IMH 判据**（staging receipt 无 `image_height_mm`）。
  IMH 在 `data/zmx` 上是第 3 大越界项（44 次），**加上它会让域内数变少**
- **口径不一致**：staging 用专利**声明值**，`data/zmx` 那 55 颗用 case index
  **实算值**，两者不是同一刻度，跨池相加只能当量级参考
- **未经真机复核**，纯离线推算

## 更正记录（两处，方向相反）

1. **「117 颗无法判被排除 → 让真数更小」——说反了。**
   排除它们让计数**偏小**，所以 41 **不是上界**
2. **命中率算错分母。** 前一版用 265（全池 receipt 覆盖数）当分母得 15.5%／
   用 205 当分母得 19.5%；**正确分母是 88**（`①∧②` 里**能判的**那些），
   命中率 **46.6%**

两处叠加，把结论方向带反了：从「staging 价值有限」变成「staging 可能接近三倍」。

**教训**：`①∧②` 的 205 里有 117 颗是**未知**而非**不合格**，
把未知计入分母就等于默认它们全不合格。**未知不是否定。**
