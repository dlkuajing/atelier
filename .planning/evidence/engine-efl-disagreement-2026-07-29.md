# 两个引擎对 41 颗对照的焦距读数差 1.5177 倍，而那正好是盖板玻璃的折射率（2026-07-29）

**一句话**：`index.json` 的 `efl_mm` 是 **Optiland** 的近轴焦距，而对照是被 **CODE V** 探针打分的；
**440 颗里 41 颗（9.3%）两者差 >2%，其中 37 颗的比值卡在 1.5177**——
那是这些设计最后一片盖板玻璃的折射率（`GLAS ___BLANK 1 0 1.517 64.2`）。
**用设计自身的几何可以判出是谁错：Optiland 对、CODE V 的导入把焦距放大了。**

## 这条为什么是可信度问题而不是精度问题

对拍器把候选优化到 `spec_efl_mm`（来自 manifest = Optiland），却拿 CODE V 去量对照。
当两者差 1.5177 倍时，候选被建成对照线尺寸的 **0.646 倍**，而 F/# 与视场角相同——
**这是一个相似变换**，横向像差随系统尺寸线性缩放，于是候选白得一个线性更小的点列径。

实测（`US-20220011544-A1-e5`，2026-07-28 pilot 记录）：

| | 候选 | 对照 |
|---|---|---|
| EFL（CODE V 读数） | 2.84062 | **4.39859** |
| F/# | 2.0 | 2.0 |
| RMS 点列径 | **1.848 µm** | **51.4502 µm** |

→ 该 metric 裁决 **`par`，ratio 0.036**。
（trial 级因 MTF 缺失判了 unmeasurable，所以它没进标题数字——**但那是运气，不是闸**。）

⚠️ **而且 2026-07-29 的视场重标把仅有的那点意外保护也拆掉了**：
重标前候选的 `tan θ` = 1.0035、对照 1.1310，同场筛会拦下它；
重标后候选被重新瞄准到对照自己的视场角，`tan θ` 两侧相同，**同场筛与口径筛双双放行**——
两条腿都是比值，**对整体缩放完全免疫**。这两颗都在当前 49 条 trial 的计划里。

## 谁错：用设计自身的几何判

直线投影下外场像高应为 `f·tan θ`，而 ZMX 里带着设计自己的 `YFLN` 与实测像高标注：

| case | 半视场 | 声明像高 | Optiland `f` | `f·tanθ` | CODE V `f` | `f·tanθ` |
|---|---|---|---|---|---|---|
| `US-20210364737-A1-e1` | 14.205° | 2.6112 | 10.3487 | **2.6197**（差 0.3%） | 15.7063 | 3.9759（差 52%） |
| `US-20210364765-A1-e3` | 26.487° | 3.1935 | 5.8525 | 2.9162 | 8.8824 | 4.4260 |
| `US-20210389571-A1-e6` | 54.522° | 1.3409 | 1.2896 | 1.8095 | 1.9573 | 2.7463 |

**Optiland 的焦距与设计自身的视场/像高自洽，CODE V 的不自洽。**
（第三颗是超广角，`f·tanθ` 本就不适用——但 Optiland 的 `f·θ = 1.2272` 仍比 CODE V 的 1.8625 更接近 1.3409。）

比值的来源几乎写在文件里：这些 ZMX 的最后一片是 `GLAS ___BLANK 1 0 **1.517** 64.2`，
和 1.5177 对得上。像空间介质被算进焦距（`f' = n'·f`）是最直接的解释，
但**具体是 CODE V 的 Zemax 导入把 `GLAS` 挂错了一面、还是别的，本铲没有定位**。

## 落地的修法：不选边，判不了就不判

**不**把 spec 改成 CODE V 的读数，也**不**继续用 manifest 的：
两个引擎读不一样的对照，就是一颗**我们没法声称已经量准的对照**。

- 对照探针**提到优化之前**跑（本来每条 trial 就要探一次，零额外真机时间），
  然后比对 probe EFL 与 manifest EFL；
- 超出容差 → `unmeasurable` / `blocked_at="control_engine_disagreement"`，
  **在花掉最贵的那一段之前**结束该条 trial；
- 两者一致时**没有选择可做**（就是同一个数），取探针值，让 spec 与打分同源。

另加一条纵深防御：`conformance_screen` 新增**绝对尺度**腿——
候选实测 EFL 必须落在对照实测 EFL 的容差内，**排在另外两腿之前**，
因为那两腿都是比值、对整体缩放视而不见。

容差沿用引擎自己的「EFL 达成」定义（`EFL_TARGET_TOLERANCE_PCT = 2%`），
不新造数字（合红线③）——优化器自己判为收敛的候选，不该在这里因同一个数被否掉。

## 代价

按 9.3% 估，49 条 trial 里约 4–5 条会被这道闸挡下。
**这是把假数换成"不可测"，方向正确**：北极星的判据是可信度，不是覆盖率。

## 未做

- **没有定位导入缺陷的确切位置**（CODE V 侧的 `ZEMAXOS_TO_CV`？我们的 `zmx_writer`？
  还是 Optiland？）。三条几何自洽证据指向 CODE V 读大了，但没有翻到那一行代码。
- 41 颗的完整清单已可由脚本重算，但**没有把它们移出语料**——本铲只在 trial 级拦，
  不动数据。
- 没有查这 41 颗的其它读数（点列径 / MTF / 畸变）偏了多少——
  如果焦距读错，同一个模型的其它量多半也不是那颗真镜头的。
