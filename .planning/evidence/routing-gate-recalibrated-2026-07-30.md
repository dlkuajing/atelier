# 产品侧路由像质闸换尺重标（2026-07-30）

前置：[`stored-routing-quality-diverges-2026-07-30.md`](stored-routing-quality-diverges-2026-07-30.md)
量化了「闸读存量 Optiland 半场半径、判决读 CODE V 全场直径」这个分歧（中位 1.72 倍、最坏
188 倍）。本页是**产品侧的修复与实测代价**。P2 侧的 seed 池闸另走 PR #155（当前仍 OPEN）。

## 改了什么

| | 改前 | 改后 |
|---|---|---|
| 比较的量 | `mtf.rms_spot_radius_um_by_field` 最大值（Optiland **半径**，94.3% 只测到部分视场） | CODE V **全场直径**（与判决同一个 `SPOTDATA` 操作数） |
| 阈值 | `_SEED_ROUTING_MAX_RMS_UM = 100.0`（注释自陈：为挡掉两颗坏 ingest 件而设） | 语料分位 **`p75 = 41.4567 µm`**，从已提交分布读出（选档理由见下节） |
| 无读数时 | 用存量值（即被质疑的那个数） | **fail-closed**：判为违规 |
| 被拒 seed 之间 | 一律 1.0，彼此不可分 | 按语料分位排序（0.5–1.0），未测量者 1.0 最差 |

**真相源选型**：新建 `app/data/corpus_routing_quality.json`（218/442 有读数），
不往 `index.json` 加列。两条实测理由：① `index.json` 是裸数组、无信封，
provenance（census 名 + sha256）无处安放，而**像质数字没有出处正是老闸出错的方式**；
② `scripts/generate_cases.py:171` 整体重写 `index.json`，CODE V 来源的列会被下一次
重生成静默丢弃——而重生成那台机器按设计可以根本没有 CODE V。

## 实测代价（跨受让人池，n = 404 个查询）

查询 = 每颗案例自己的 spec；池 = 全部跨品牌案例。**必须跨品牌**：全库池里
老闸的「参数匹配好」有一大半是路由到同一专利的兄弟实施例（EFL 偏差中位
3.4% vs 跨品牌 22.1%），那是测量假象不是能力。

| | 老闸 | 新闸 @ p75（交付档） |
|---|---|---|
| 路由到**无全场读数**的 seed | **219/404** | **8/404** |
| 路由 seed 的 CODE V RMS 中位（已测 n） | 14.22 µm (n=185) | 11.80 µm (n=396) |
| 同上 p90 | 443.82 µm | **101.27 µm** |
| 路由 seed > 100 µm 的**比率** | 32/185 = **17.3%** | 44/396 = **11.1%** |
| EFL 偏差 中位 / p90 | 22.1% / 92.0% | **28.9% / 94.3%** |
| FOV 偏差 中位 / p90 | 2.20° / 4.80° | **3.55° / 8.29°** |
| 路由到荒谬读数（>1e6 µm）的 seed | 0/404 | **2/404** |
| 改判 | — | **243/404** |

（同表 p50 档：中位 7.11 µm 更好，但 >100 µm 比率 13.9%、荒谬 4/404、EFL 偏差 30.0%/118.1% 都更差。）

⚠️ **绝对条数会骗人**：老闸 32 条 vs 新闸 55 条不是变差——分母从 185 变成 396。
老闸那 219 条路由到「没读数」的 seed，真实像质根本不知道，而在 94% 半场低估的语料里
它们大概率不好。按比率比才对：17.3% → 13.9%。

## 两处诚实的代价

**① 参数匹配确实变差**（EFL 中位 22.1% → 30.0%，FOV 中位 2.20° → 3.47°）。
阈值扫描（最终代码，被拒带下限随受测分位同步移动）显示这**不是阈值定高了**：

| 分位 | 阈值 µm | 路由 RMS 中位 | 路由 >100 µm | EFL 偏差中位 | FOV 偏差中位 |
|---|---|---|---|---|---|
| p25 | 5.611 | 5.61 | 55 | 33.1% | 3.23° |
| **p50（采用）** | **10.231** | **7.11** | **55** | **30.0%** | **3.47°** |
| p75 | 41.457 | 11.80 | **44** | 28.9% | 3.55° |
| p90 | 400.655 | 21.88 | 91 | 29.5% | 3.57° |

四档的参数代价**基本是一条平线**（EFL 28.9–33.1%，FOV 3.23–3.57°）⇒ 这笔钱不是阈值付的，
而是**语料里好的镜头不在 spec 所在的位置**，任何真闸都要付。

⚠️ **更正我自己（两次）**：先前这里写「p50 在质量上支配 p75」，重跑后**不成立**——
p75 的 >100 µm 路由更少（44 vs 55），只是中位更差（11.80 vs 7.11）。
随后**采用档也从 p50 改成 p75**，理由见下节，不是我一开始想的那样。

## 为什么是 p75 而不是语料中位

**准入与竞争力是两个问题，闸只能回答一个。** seed 要**竞争**的是读 2–11 µm 的对照，
但路由**必须返回现存最好的一颗**——拒收造不出更好的。按分位数逐档实测准入：

| 分位 | 阈值 µm | 原始真实设计（骨干）准入 | 专利案例准入 | 全库准入 |
|---|---|---|---|---|
| p25 | 5.611 | **0/29 有读数** | 56/189 | 56/218 |
| p50 | 10.231 | **8/29** | 101/189 | 109/218 |
| **p75（采用）** | **41.457** | **27/29** | 136/189 | 163/218 |
| p90 | 400.655 | 29/29 | 167/189 | 196/218 |

**p25 一颗骨干都不准入**——39 颗原始真实设计在 CODE V 全场下**全部**差于 5.61 µm。

决定性个例：`test_optical_match.py:1551` 钉死的旗舰 seed `5P_F1.8_FOV74.1`，
其注释写「image-quality healthy（max RMS ~8.1µm, 1.0 field）」——那 8.1 µm 正是本次
不再采信的**半场半径**；它 CODE V 全场读 **19.33 µm**，被 p50 挡掉、被 p75 准入。

**A/B 判据（非点前缀路径，基线臂 = 本 commit 的父提交 4a9f6be7）**：

| 臂 | `tests/test_optical_match.py` |
|---|---|
| 基线 4a9f6be7 | **25 passed** (16:07) |
| 新闸 @ p50 | **13 failed** |
| 新闸 @ p75 | **25 passed** (16:35) |

⇒ p75 在 `test_optical_match.py` 的 **25 条钉死行为上一条不破**，同时仍以 **10.8 倍**余量
拒掉那颗 447.60 µm 的 `US-12436366-B2-e10`，并拒掉全部 5 颗 >1e6 µm 的荒谬读数。

小文件组同样双臂对照（`test_fno_probe` / `test_orchestration_*` / `test_tolerance_table` /
`test_wavefront_metrics` / `test_zmx_import_prep` / `test_seed_target_score` / `test_seed_routing`）：
基线 **208 passed**、p75 **1 failed / 207 passed** —— 唯一那条见下节。
⚠️ 顺带确认：全量里 `test_fno_probe` 3 条 + `test_zmx_import_prep` / `test_tolerance_table` /
`test_wavefront_metrics` 各 1 条在**非点前缀路径下双臂全绿** ⇒ 那 6 条是
「worktree 路径含 `.claude` 点前缀」的环境失败，与本改动无关
（`ensure_codev_safe_input_path` 直接拒点前缀路径组件）。

## 唯一那条真失败：自适应 FOV 上限的锚点移动了（已重锚）

`test_orchestration_generators.py` 的 ultrawide anchor 边界测试。实测机制：

| | 旧闸 | p75 闸 |
|---|---|---|
| fov=98.0 候选池 | 11 颗，anchor 不在 | 18 颗，anchor 第 3 |
| 池内最大 \|FOV 失配\| | **4.45°** | **8.5°** |
| fov=98.5 第一名 | anchor（58.57 µm） | `US-11668898-B2-e5` |

上限 = `max |FOV 失配|` over primary top-10 席位，这个**结构没变**，变的是席位：
像质更干净的 seed 往往 FOV 更远（全局 FOV 偏差中位 2.20° → 3.55°），席位一换上限就宽。
原断言钉的是旧池组成而非不变量；反强拉不变量由该文件 525-640 行**六条合成池测试**独立锁定
（含 `..._cap_anchored_to_old_codev_seats_not_primary_max`），改闸后全绿。
⇒ 重锚为「anchor 自身 58.57 µm 属被拒档，两个 target FOV 下都不能拿第一名」——
用像质表达，因为 case_id 每个 ingest 批次都会漂。

⚠️ **重锚第一版我写错了**：在测试里复刻了 cap 的算法，池用成全库而非场景池，
得出 8.0 与真实 8.5 冲突。**在测试里复刻实现就是在测自己的复刻件** ⇒ 删掉该断言。
**收紧到 p50 以上会改变演示现场能路由到哪些镜头 = 产品范围决策，不是标定** ⇒ 上交主公裁定，
代价已量化（路由 RMS 中位 11.80 → 7.11 µm 更好，但骨干准入 27/29 → 8/29）。
P2 比较器那侧可继续用 p50——**两侧共用同一个「量」，不必共用同一个阈值**；
`tests/test_seed_routing_quality.py` 断的是量，不是阈值。

**② 4/404 条路由到 CODE V 读 3.2e20 µm 的 seed（老闸 0 条）。根因已定位且不是本闸**：
`US-11719917` 与 `US-12032139` 两族共 8+ 颗案例的存量 `image_height_mm` 是
**1e17–1e18 mm** 量级，把 `_norm_delta` 的 imh 跨度撑爆 ⇒ 全库 imh 距离一律 ≈ 0
（imh 权重 0.30，是第二大维），而这几颗自己在该维上看起来完美匹配。实测：
删掉最坏那颗，路由就落到它的兄弟（3.196e20 → 3.231e20）。
**它们不在 `corpus-fidelity-quarantine.json` 的 55 条隔离名单里。**
修它属于路由归一化 / 语料隔离层（影响大），不在本铲范围，已单独记账。

**曾走错一次**：我先试了 P2 判决那道「光斑不可能大于自己的像圈」筛，
在这几颗上**自我抵消**——光斑和像高同时是天文数字，筛出 0 条。所以任何依赖
存量 index 元数据的健全性筛都救不了它们；可靠判别器是隔离名单。

## 路由赢家 golden 重锚（215/445）

`tests/data/eval_golden.json` 钉的是**每个 brief 路由选中哪颗 seed**。路由既然合法改变，
就按仓库既定做法 `uv run python scripts/e2_golden.py` 重生成（该脚本的存在理由原文：
「每个 ingest 批次都会改变赢家……让批次重锚变成『跑这个 + 审 diff』」）。

**两个策略的代价已分开量**（同一批 442 条可比 golden）：

| 变体 | 路由改判 |
|---|---|
| 只有阈值（p75，无读数不判违规） | **60/442** |
| 只有 fail-closed | **168/442** |
| 两者（实际交付） | **215/442** |

⇒ **主要代价来自 fail-closed，不是阈值档。**

改判去向：patent→patent 177、native→native 19、**patent→native 16**、**native→patent 3**
⇒ 骨干净增 13，不是被抛弃。

买到了什么：被换掉的 215 颗 seed 里 **196 颗原本没有全场读数**（旧 19 颗有读数者中位 77.13 µm）；
换成的 seed 199 颗有读数、中位 11.80 µm。全部 445 条 golden 上，
**路由到「无全场读数」seed 的 brief 从 218 降到 38**。

⚠️ **不要读成「像质变好了」**：445 条上中位 10.39 → 11.00 µm、>100 µm 从 15 变 24，
看着像变差，但**被测子集本身从 227 变成 407** —— 这是成分陷阱，不是退化。
按比率是 6.6% → 5.9%，略有改善。**诚实的说法只有一句**：
路由 seed 中「质量未知」的从 218 降到 38，而已知者的分布没有明显移动。

⚠️ 最大值 8.261e20 µm **两侧完全相同** —— 那颗荒谬读数的 seed 仍被某个 brief 选中。
它属于上一节 ② 的存量像高缺陷，本闸挡不住（penalty 已给到最差 1.0，但归一化被撑爆的
imh 维让它在参数上「完美匹配」）。已单独记账。

## 我自己引入又修掉的一处站不住的排序

第一版把「未测量」判为 penalty **1.0 = 池里最差**，于是它排在一颗**已测 447 µm** 的镜头
**之后**——等于说我们宁要一颗已知很差的，也不要一颗只是没测过的。**未知 ≠ 已知很差。**
改为：未测量在**被拒带内部**取语料中位分位（0.5），仍然输给每一颗准入的 seed
（这才是 fail-closed 的含义），但不再输给被实测判定比语料中位还差的那些。

## 未收口的一条：3/13 个 eval brief 的像高/FOV 要求达不到（待裁定）

`scripts/evaluate_design_agent.py`（13 个 eval case，双臂实测）：

| | 基线 4a9f6be7 | 新闸 |
|---|---|---|
| passed | **9** | 6 |
| failed | **4** | 7 |

⚠️ **基线本身就不绿**——已有 2 条 `image height 2.80/2.85 >= 2.90` 在漏，这个契约不是被本次改动
第一次破的。新增 3 条：`ui_high_fov_default_request_stays_blocked`（FOV 83.4 >= 84.0）、
`patent_ultrawide_6p_fast_reanchor`（imh 3.04 >= 3.20）、
`patent_ultrawide_6p_extreme_fov_reanchor`（imh 2.63 >= 2.90）。
其中最后一条被 `tests/test_eval_golden_seeds.py::test_patent_golden_fail_on_regression_case_runs`
以 `--fail-on-regression` 钉住 ⇒ **该测试目前红，是本分支唯一的红**。

**根因（已实测，不是推断）**：那条 brief 请求 imh 2.964 mm。改判后赢家
`US20210165194A1` imh 2.626（codev 8.75 µm，准入）；第 6 名 `US9239447B1` imh 3.036
（codev 7.12 µm，**准入且满足要求**）却排在 d=0.3633 vs 0.0477。距离分解显示
**`imh_part` 对每一颗都是 0.0** —— ultrawide 池的 imh 归一化跨度是
`0.145 .. 8.28e17 mm`，0.27 mm 的失配归一化后就是 0。权重 0.30 的这一维是死的。
主导的是 FOV（权重 0.46）。

⚠️ **阳性对照推翻了我的第一个假设**：我以为这就是上文 ② 那个 1e17 存量像高缺陷，
于是把 >100 mm 的成员排除出跨度重测——跨度变成 `0.145 .. 44.663 mm`，
0.27 mm 失配归一化只有 **0.0061**，**赢家不变**。所以这条**不是**那个缺陷造成的，
而是「imh 以整个语料跨度归一化，因此亚毫米级的硬要求在距离里天然不可见」。

⇒ **三条路，我不替主公选**：
① 接受这 3 条能力回退，把 `--fail-on-regression` 的期望重锚（**削弱一条能力契约**）；
② 让路由把像高当硬要求（`_seed_spec_guard_penalty` 现有 0.35 mm 门限恰好比本例的
0.338 mm 高一点——**照这个数去调就是拿常数拟合结论，我没做**）；
③ 放宽 fail-closed（与「空洞必须 fail closed」的指示冲突）。

## 分位闸的失效方向（自陈，未加护栏）

分位闸会随参考人群变差而**变松**：灌进 500 颗坏镜头，p50 就跟着抬高。这是 **fail-open**。
接受它的理由是替代方案又是一个没人量过的绝对数——正是本次要改掉的错误；
护栏是 `corpus_quality_distribution.json` 自带 `n` 与 census sha256，
**人群变了会出现在 diff 里而不是静默发生**。
