# 阳性对照没过——所以我收回一个还没说出口的结论（2026-07-29）

**一句话**：我本来要断言「语料的存量像质数是在**一半视场**上算的、因此偏好看」。
阳性对照直接否掉了这个说法：**用今天的代码、按语料自己存的那个 `fov_deg` 重算，
22 例里只有 1 例落在存量值的 ±5% 内**（中位 1.43，范围 0.96–1.88）。
存量像质**根本就不是今天的代码能复现的数**——这个更窄的结论才是真的，而且更该在意。

## 假说是怎么来的

`app/core/case_library.py` 生成每颗 case 的 MTF 走
`regularize_fields_to_angle(optic, nominal_fov_deg)`，而该函数取 `full_fov_deg / 2` 当半角。
既然 `fov_deg` 有 253 颗存的是**半角**（`fov-unit-mix-2026-07-29.md`），
那这些 case 的像质就该是在真视场的一半上量的——听起来严丝合缝。

## 阳性对照：先证明这条链能复现已知结果

抽 30 颗（跨步取样，非取前 30），对每颗用**旧的** `fov_deg` 重算最大 RMS 点列径，
与存量值比：

| | |
|---|---|
| n | 22（另 8 颗 Optiland 算不出来） |
| **落在 ±5% 内** | **1 / 22** |
| 比值 min / p25 / **中位** / p75 / max | 0.96 / 1.12 / **1.43** / 1.61 / 1.88 |

**没过。** 今天的代码即使按语料自己存的视场重算，也复现不出存量数字。
所以「存量像质 = 半视场上算的」**不成立为已证结论**——生成语料到现在之间还变过别的东西
（ingest 修复 E1-01/E1-02、稳健裁剪的引入、Optiland 版本）。

> 这正是 `feedback-measurement-traps` 里「阳性对照先行」那条的用处：
> 它拦下的是一个我已经写进了草稿、听起来完全讲得通的结论。

## 不依赖存量数的那半个实验，结论是稳的

同一个引擎、同一颗镜头，只改视场（旧的一半 → 重锚后的真值）：

| | |
|---|---|
| 两侧都算得出 | 12 |
| **真视场读数 / 半视场读数 > 1** | **12 / 12** |
| 中位 | **1.584** |
| max | 409.2（离群） |
| Optiland 算不出来 | 旧视场 **8/30** → 真视场 **18/30** |

**在真视场上量，每一颗都更差，中位差 1.58 倍，而且追迹失败率从 27% 涨到 60%。**
这条不依赖存量值，是引擎内部的自比较。

## 落到北极星上的两件事

1. **存量像质不可复现** ⇒ 任何依赖它的判断都欠一份说明：
   `rank_seeds` 的质量维（`_seed_floor_gap` / `_seed_has_floor_violation`）读的就是它，
   演示界面读的也是它。这不是"数字略有出入"，是**不知道那些数是怎么来的**。
2. **重锚只改了标、没重算数** ⇒ `fov_deg`/`scenario` 现在是对的，
   而同一份文件里的 MTF/RMS 仍是旧的，两者**不自洽**。重算是必须做的一铲，
   但要连带解决 Optiland 在真视场上 60% 算不出来的问题——
   而按项目既有认知，Optiland 算不出来**不等于**镜头坏（CODE V 追得出的样本已实测存在）。
