# 底库可追迹率普查 · 2026-07-28

**一句话**：全库 442 颗 seed 中 **315 颗（71.3%）能产出可用的 RMS 点列径**，127 颗（28.7%）不能；
失败根因**尚未确定**，但五条最可能的假设已被数据排除。

> **措辞精确性（本文初稿曾写成「无实光线穿过」，实测后更正）**：失败并不等于「一条光线都过不去」。
> 逐视场探针（4 颗，2026-07-28）实测：失败 seed 的**轴上视场 `SPOTDATA` 返回 err=0（成功）但点列径
> 恰好为 `0.0`**，边缘视场返回 `err=-1`（彻底失败）；对照 seed 两个视场分别为 1.33µm / 5.61µm。
> 所以准确说法是「**没有任何视场产出可用的点列径**」。这也是「退化值恰好等于完美值」陷阱的
> **第三个实例**——前两个在宏的累加器初值里（见 PR #93），这一个在 `SPOTDATA` 自身的返回值里。

## 为什么测这个（北极星关联）

`.planning/NORTH-STAR.md` §3：P1 产出能力要「一次运行在 `N` 个独立需求上零介入产出 `M` 个
完整交付物」，P2 异源打平率要「底库 442 颗真实设计」当统计对照组。

**一颗没有任何实光线能穿过的 seed，既产不出像质指标（四件套缺件），也当不了对照组。**
所以可追迹率直接封顶 `N` 与 P2 对照组规模——它是这两个待实测数值的上游约束。

## 方法

导入后**不做任何优化**，只算 `@rmssum`（RMS 点列径）与 EFL。判据：

> **RMS 点列径 > 0 即证明至少一个视场追迹成功。**

依据是它的**正定性**——衍射给出严格大于零的下界，故 `0.0` 只可能是宏累加器的初值
（`^max == 0`，见 `codev_optimize._metric_function_block`）。这与生产解析层现在采用的判据
是同一条（PR #93）。刻意不算 MTF / RMSWE：它们是昂贵调用，且对本判据无增量信息。

**口径边界**：本普查测的是 **`seed_baseline` 态**（导入后、任何 setup 之前），与
`build_codev_target_sequence` 的第一个快照同态。生产随后会施加 F# 与渐晕；因此
71.3% 是**可用率的下界**，不是终值。已实测的一条：渐晕**救不回**失败样本（见下）。

红线①：每次 run 前断言 CODE V 会话数（父进程非 codev/codevm 的 codev/codevm 进程数）为零，
442 次全程为零。

## 已排除的假设（每条都有数据，不是推断）

1. **渐晕 / 光瞳裁切无效** —— 对 4 颗失败样本爬完生产渐晕阶梯（0.0→0.7），**0/4 回收**；
   对照样本在 edge=0.0 即正常。机制自洽：渐晕裁的是光瞳**边缘**，而主导报错是主光线
   找不到，**主光线在光瞳中心，裁不到它**。
   → 这**推翻**了 `project-stagec-46-blocked-root-cause` 里「渐晕/裁剪方向对这一类有效」的推测。
2. **`RAIM` / ray-aiming 不是判别变量** —— 头部普查显示 `RAIM` 在 39 颗可工作格式中
   39/39 存在、403 颗专利 seed 中 0 存在，看似完美相关；但官方宏源码
   `zemaxos_to_cv.seq:956` 写明 `! Ray aiming (not needed in CODE V)`，**该字段被整个忽略**，
   只打印一条提示。相关性是伴生的，不是因果。
3. **视场角不是判别变量** —— 可追迹组半场角 median 38.1°、失败组 40.0°，p10/p90 大幅重叠；
   分档可追迹率无单调趋势（80–89° 反而 100%，20–29° 仅 55%）。
4. **片数不是判别变量** —— 两组 `SURF` 数分布相同（median 均为 17）。
5. **`CRADJ` 无效** —— CODE V 报 `Unable to find chief ray` 时自荐 `Use CRA command`，而 CODE V
   自带官方宏 `CV_MACRO:CRADJ`（「把主光线移到渐晕光瞳中心」，其唯一限制「有限共轭 + XAN/YAN」
   对无穷远共轭的手机镜头不适用）。对 10 颗主光线失败样本做单变量对照：
   **基线 10/10 复现失败，CRADJ 回收 0/10**。即 CODE V 自己推荐的杠杆也救不回来。

## 两个附带发现

**「可追迹」≠「可用」。** 追迹成功的样本里存在极差设计：`US-20210389571-A1-e3` 的
RMS 点列径达 85.7 / 316.4 µm（Optiland）与 94.4 µm（CODE V）。P2 对照组需要在可追迹之下
再设一道质量门，本普查未定义该门（**禁止先验拍板**，须实测后定）。

**Optiland 不能当免费预筛。** 首轮 n=8 曾 8/8 一致，据此以为可零成本预筛；扩到 n=28 后
一致率降为 **26/28（92.9%）**，两个方向各有一例不一致
（`5P_F2.0_FOV78.7…`：CODE V 失败 / Optiland 成功；`US-10120164-B2-e4`：CODE V 成功
rms=399.76 / Optiland 失败）。**n=8 的完美一致是小样本假象**。Optiland 全库普查因
~2 分钟/颗（约 15 小时）而中止。

## 尚未确定 / 下一步

- **127 颗的根因未定。** 五条假设已排除，搜索空间已显著缩小。已知的最锋利事实是
  **失败集中在边缘视场**（轴上 `err=0`、边缘 `err=-1`），且**任何 setup 侧杠杆都无效**
  （渐晕、CRADJ 均 0 回收），这把嫌疑推向**处方数据本身**——即 seed 生成环节
  （`scripts/patent_to_zmx.py`）可能对约 29% 的专利 seed 产生了非功能性处方。
  该方向**尚未验证**，验证方式是拿失败 seed 的处方与专利原表逐面对拍。
- **轴上点列径恰好 `0.0` 需单独归因**：它与「只有中心一条光线存活」的形态一致
  （单点必然 RMS=0），但 `EPD=1.53mm`、`FNO=2.2` 读数正常，两者尚未对上，不下结论。
- **29 颗「无 ERROR 行」是另一类退化**，`SPOTDATA` 返回错误码但 listing 不打印，需单独归因。
- **71.3% 是下界**：施加 F# / AUT 之后的可用率未测（渐晕与 CRADJ 已证无效，F# 未测）。
