# seed 质量阈值的参考总体：把漂移量清楚，选项交主公（2026-08-03）

## 问题

`default_seed_quality_limit_um()` 的 docstring 写着「**语料中位数，不是谁选的数**」。
这句话是对的，也正是陷阱所在：它讲的是**出处**，不是**稳定性**。
阈值是参考总体的一个统计量，**总体一动它就动**——而最可能动它的，
恰恰是本项目排在最前面的那一铲（把 staging 颗粒并进语料）。

实测（本仓 2026-08-03，过 promotion 闸①–⑤ 的 187 颗）：

| | n | p50 |
|---|---|---|
| 今天 | 218 | **10.2312 µm** |
| 并入 187 颗后 | 405 | **11.4262 µm（+11.7%）** |

⇒ 「≤ 语料中位」这道闸**在并库前后筛的不是同一批东西**，而两侧的「达标数」
会被直接拿来比。**阈值和计数会同向移动，且没有任何地方记着这件事。**

## 本 PR 做了什么（不做什么）

**做**：让这个数**永远带着分母走**。新增 `seed_quality_limit_basis()`，返回

```json
{
 "limit_um": 10.2312,
 "statistic": "p50",
 "population": "data/zmx (442 committed case ZMX)",
 "criterion": "no CODE V error and every declared field produced a positive per-field SPOTDATA reading (n_positive == num_fields)",
 "quantity": "max over fields of CODE V's RMS spot size, in um -- a diameter, not a radius",
 "n": 218,
 "census_run": "trace-census-20260728",
 "census_sha256": "fdfe52b6…"
}
```

字段**全部从分布产物自己的键复制**，不是另写一份描述——描述会和它描述的对象漂开。
`p2_pair_census.census()` 与两份供给产物现在都记这一块。

`app/core/corpus_quality.py` 的 docstring 早就写下了这条规矩：
> We report the number and name the denominator.

而一个裸 float **没有命名任何分母**。本 PR 只是让代码追上这句话。

**不做**：**不改参考总体**。那是主指标路径上的 live 判据，按自主度矩阵属「影响大」，
且「哪个总体才对」是个真问题，不该我单方面拍。

## 交主公裁定的选项（三个都已实测，当前语料）

| 参考总体 | n | p50 | 对「加入域外料」的抗性 |
|---|---|---|---|
| **A. 全部有全场读数**（今天） | 218 | **10.2312** | 无——并库直接推高 +11.7% |
| B. 过「可追迹 + 保真度」两闸 | 192 | 10.0735 | 弱 |
| **C. 产品域内**（= 对照池） | 74 | **9.7121** | 强——并进来的多数是域外料，不进分母 |

三者今天相差 **<5%**，所以**改口径本身几乎不动阈值**；差别全在**以后**。

**倾向 C 的理由**（供参考，非决定）：这道闸问的是「这颗 seed 值不值得作为起点」，
而候选最终要和**对照**比。用对照所在的总体当尺子，语义上是
「seed 至少要和我们被拿来判的那批镜头的中位数一样好」，
且它对「并入域外料」天然免疫——而那正是下一铲的主要进料。

**倾向 A 的理由**：它是最大的样本，且不依赖 screen 3——而 screen 3 本身
（按 `upstream-supply-funnel-2026-08-02.md` 第三节）是个**对照侧**判据。

## 在主公裁定之前，怎么报数才不算欺骗

扩库前后对比**必须两侧用同一个冻结阈值**各算一遍，再**另外**报「阈值本身移动了多少」。
这两件事分开说，否则读者会把「尺子变了」读成「东西变好了」。
（本项目陷阱清单第 9 条，2026-08-02 记。）

## 诚实边界

- 三个 p50 都算在**今天**的语料上；并库后三者各自会变多少**没有测**
  （需要先把 187 颗建成 case 才知道它们的 domain 归属）。
- 本 PR **不改任何数字**：`p2_pair_census` 仍是 59 trials / 74 usable，
  两份供给产物的头条数字逐项不变，只是多了一块 `seed_quality_limit_basis`。
