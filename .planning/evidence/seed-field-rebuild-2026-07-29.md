# 视场重建：让候选回答被问的那个问题（2026-07-29）

**一句话**：优化前把 seed 的 `YFLN` 重标到 spec 的外场角，候选从此在**与对照相同的视场**
上被优化和评价；**425/442** 颗底库 ZMX 可重标（余下 17 颗是原生 `FTYP 3` 的真实设计）。

## 为什么只改视场角，不同时钉像高

EFL 由 AUT 锁到 target、视场角由本模块锁到 spec 后，两侧的近轴参考量 `EFL·tanθ`
**逐位相同**。畸变的定义正是相对这个参考量的，所以「有没有把要求的视场落到要求的
靶面上」这件事，**已经完整地由畸变这一项承载**——而畸变本来就是 NORTH-STAR §3
三项判据之一。再加一条独立调参的像高约束等于把同一件事数两遍，还平白多一个旋钮。

## 只改一行

只重写 `YFLN`。字段类型（`FTYP 0`）、字段个数、轴到边的采样比例**全部保持原样**——
渐晕块与 `autovig` 都按**位置**寻址字段，重采样会静默改变它们指向谁。
编码与行尾经 `decode_zmx_text`/`encode_zmx_text` 逐字节往返，UTF-16 seed 仍是 UTF-16。

## 兜底一律 fail-closed，且在花 CODE V 时间之前

对照非角度型（`FTYP 3`，`YFLN` 是毫米不是度）→ `control_field_not_angular`；
seed 不可重标（斜视场 / 单视场 / 全轴上 / 缺行）→ `seed_field_not_rebuildable`。
两条都**在启动 CODE V 之前**返回。单条 trial 46 分钟，诊断不该等到跑完。

## 顺手抓到的一条：配对为什么会差两倍视场

它把一颗 **18.35°** 的 seed 配给了 **37.5°** 与 **33.1°** 的对照。
消融实测（`trace-failure-ablation-2026-07-28.md`）里主导的失败模式就是**视场受限**，
而这里有一半的配对开局就要把视场撑到两倍。

⚠️ **更正我自己的第一反应**：我起初写的是「`rank_seeds` 完全不看视场」，**这是错的**。
它给 `fov` 的权重是 **0.46，全部维度里最大的一个**，另有 `fov_miss > 5°` 的硬惩罚。
真正的病灶在**它读到的那个数**——见
`.planning/evidence/fov-unit-mix-2026-07-29.md`：`index.json` 的 `fov_deg`
**253 颗存的是半视场、172 颗存的是全视场**，而 schema 写的是「Nominal full FOV」。
路由里权重最大的那一维，比的是两种单位。
