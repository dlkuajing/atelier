# Quick Task 260714-o01: strict preregistration and ITT protocol kernel

## Goal

Implement the first O-01 code slice from the clean reviewed and released
`origin/main@42803f8d`. The result is a deterministic, fail-closed, in-process module that accepts
immutable preregistration facts, freezes exact identity and eligibility content, and recomputes
raw ITT reports. It prepares later O-nodes but cannot authorize confirmatory work or make any
north-star gate true.

## Design seam

Use one deep module with two operations:

1. freeze a preregistration specification into exact ordered mapping, eligibility, and complete
   freeze content whose domain-separated hashes are recomputed from inline values; and
2. recompute pipeline and candidate-slot ITT reports from that frozen object, a separately supplied
   expected freeze-content hash, and typed but explicitly unverified observations.

The public interface exposes immutable values and reports. Continuous ordinals, parent lookup,
closed terminal/retry maps, exclusion default-deny, evidence availability, and confidence/report
bookkeeping stay private. Duplicate evidence and verified machine-terminal evidence remain unavailable
in this slice. No adapter is added because this slice has no external system dependency.

## Scope boundaries

- In scope: pure Python, immutable strict models, canonical JSON SHA-256 domains, closed enums,
  complete freeze-content binding, fail-closed validation, raw counts, rejected exclusions,
  dependence clusters, and offline tests.
- Out of scope: schema-anchor ratification, cryptographic signature verification, pre-label artifact
  freeze, real expert label envelopes, CI/release evidence objects, machine launch/receipts, TOR,
  holdout access, and any A-F/GO transition. Those remain assigned to later backlog nodes.
- The code may represent the absence of verified expert evidence and must count it as zero. It must
  not accept caller-submitted expert pass booleans as authoritative evidence.
